# 插件开发手册

> 面向插件开发者与 AI 助手的插件开发指南：如何开发一个符合本项目规范的内置插件。
> 本文以**签名级准确**为第一原则——所有 API 均从 `src/plugin/` 实现提取。
> 配套深读：`docs/插件系统设计.md`（设计动机）、`docs/插件系统-已实现概览.md`（实现盘点）、`docs/插件UI注册与渲染设计.md`、`docs/插件模态面板.md`。示例插件：`plugins/hello/`（教学演示）、`plugins/ai/`（真实功能级插件）。

## 一、快速开始

### 1.1 最小可用插件

```ts
// plugins/my-plugin/index.ts
// 入口文件必须叫 index.ts（或 index.js），必须默认导出 AideaPlugin
import type { AideaPlugin, PluginContext, PluginManifest } from '@/plugin/adapter'
import { adapter, SDK_VERSION } from '@/plugin/adapter'
import MyPanel from './MyPanel.vue'

/** ① 清单：id 必须与目录名一致 */
const manifest: PluginManifest = {
  id: 'my-plugin',           // 命名空间 id，禁止含 ':'，须与目录名 my-plugin 一致
  name: '我的插件',           // 管理面板显示名
  version: '0.1.0',
  description: '一句话说明插件做什么',
  author: 'aidea',
  sdkVersion: SDK_VERSION,   // 必填，当前必须为 '0'（全等比对，不匹配直接禁用）
}

/** ② 命名空间作用域：模块顶层确立一次（for 有模块级缓存，同 id 返回同一实例） */
const scope = adapter.for(manifest.id)

/** ③ 插件本体 */
const plugin: AideaPlugin = {
  manifest,

  // setup 必须是同步函数；只做「注册 UI + 只读查询」，写操作由用户交互触发
  setup(ctx: PluginContext): void {
    ctx.register.registerPanel({
      id: 'main',                 // 插件内短 id：非空、不含 ':'、不含空白
      title: '我的面板',
      component: MyPanel,
      defaultPlacement: 'left',   // 缺省 'right'
    })

    // 需要卸载清理的副作用（window 监听、定时器等）在此登记：
    ctx.onDispose(() => { /* cleanup */ })
  },
}

export default plugin
```

### 1.2 让插件生效

- 插件由编译期 glob 自动收集（`import.meta.glob('../../plugins/**/index.{ts,js})`），**新建目录即被发现，无需注册清单**。
- 启用/禁用：设置 → 插件。启停只记录意愿（`localStorage('aidea-plugins')`），**重启应用生效**。
- 验证标准与主程序一致：`npm run type-check` 零错误 + `npm run test` 全绿。Canvas 渲染效果需人工在浏览器确认。

## 二、核心概念

| 概念 | 说明 |
| --- | --- |
| **manifest** | 插件清单，`id` 是跨加载方式共享的唯一路由键（UI 登记 key、additions 键、config 文件名都由它派生） |
| **setup(ctx)** | 唯一装载入口，同步执行；在此注册 UI、登记清理函数。**注册与数据操作分离**：UI/快捷键注册走 `ctx.register`（归因不可伪造），数据读写走全局 `adapter` |
| **adapter** | 全局单例 SDK（`import { adapter } from '@/plugin/adapter'`）。`adapter.api` 九域应用能力；`adapter.for(id)` 插件命名空间能力 |
| **归一 key** | 插件一切登记/数据键自动拼前缀：`${pluginId}:${id}`。插件内部只见短 id，**禁止自拼完整 key** |
| **登记总表** | `uiRegistry` store 是唯一登记表（内置目录 seed + 插件注册，条目带 `origin: 'plugin'` 归因）；layout/设置/快捷键/右键菜单消费点实时派生渲染 |

**能力速览**：

```
adapter
├─ api（九域共享能力）
│   node / connection / tag / project / view / presets / theme / file / shortcuts
└─ for(pluginId) → PluginScope（命名空间能力）
    ├─ additions   项目级扩展数据（随项目文件保存、写操作入 undo）
    ├─ config      插件自身配置（应用级持久化，不入项目历史）
    └─ modal       本插件模态运行时（open/close）

ctx（setup 注入）
├─ manifest / onDispose(fn)
├─ register  七类 UI 注册（面板/顶栏按钮/设置栏目/右键菜单/快捷键动作/模态/浮动层）
└─ modal     与 scope.modal 同工厂
```

## 三、manifest 规范

```ts
interface PluginManifest {
  id: string            // 必填；非空、不含 ':'；必须与插件目录名一致
  name: string          // 必填
  version: string       // 必填
  description?: string
  author?: string
  sdkVersion: string    // 必填；与 SDK_VERSION 全等（当前 '0'）
}
```

装载校验（`manager.ts`，任一不过该插件置 `error`，不影响其他插件）：

| 校验 | 失败表现 |
| --- | --- |
| 缺 manifest / 缺 id | error「无效的插件清单（缺少 manifest.id）」 |
| `manifest.id !== 目录名` | error「插件 id(…) 与装载源(…)不匹配」（路由键仍取目录名） |
| `sdkVersion !== SDK_VERSION` | error「SDK 版本不匹配：插件需要 X，当前 0」——**全等字符串比对** |
| 缺 `setup` | error「插件模块缺少 setup（入口需默认导出 AideaPlugin）」 |

## 四、数据操作：adapter.api 九域

**总则**：

- **查询**返回可直接使用的快照/引用（差异见下），**命令写**经 `useCommands` 自动入历史（可撤销）。
- 多步写合并为单条历史：`api.project.beginBatch()` / `commitBatch()` / `rollbackBatch()`。
- 命令层写方法预留可选尾参 `user?: string`（操作者归因），**当前版本不消费**，可忽略。
- 不可撤销的操作均明确标注（tag 全域、presets/theme/view 域、`node.stripTagFromAllNodes`）。
- ⚠️ **数据写必须走 adapter.api**（内部走命令层入历史）。禁止 import 主程序 store 直接写数据。

### 4.10 作用域能力：additions 与 config（`adapter.for(pluginId)`）

```ts
// additions：项目级扩展数据。完整键 = `${pluginId}:${key}`；key 含 ':' → throw
// 读写自动深拷贝；随项目文件 additions 字段保存/打开；卸载后键保留
get(key: string): unknown            // 深拷贝快照；无键返回 undefined
has(key: string): boolean
keys(): string[]                     // 仅本插件的 key（已去前缀）
set(key: string, value: unknown): void  // 一次 set = 单条历史（入 undo + 标 dirty）；多步用 beginBatch 包裹
remove(key: string): void            // 键不存在为 no-op（不产生历史）

// config：插件自身配置。存储 `aidea-plugin-config.<pluginId>`；即时持久化；不入项目历史/undo；不随项目走
get<T>(key: string, fallback: T): T  // 键不存在返回 fallback
set(key: string, value: unknown): void
remove(key: string): void            // 键不存在为 no-op
```

选择建议：**项目相关数据 → additions**（换项目隔离、可撤销、随文件分发）；**应用级偏好/凭据/缓存 → config**。

## 五、UI 注册：ctx.register 七类

**总则**：

- 短 id 规则（`isValidShortId`）：**非空、不含 `':'`、不含空白**。
- 登记 key 一律归一为 `${pluginId}:${id}`；**注册只增不改**：非法 id / key 冲突 → `console.warn` + 跳过（不抛错，其余注册项继续生效）。
- 各方法返回值不同：面板/顶栏/设置栏目/浮动层返回 `void`；右键菜单/快捷键/模态返回 `{ ok: boolean; conflict?: ... }`（建议检查并 warn）。
- 描述符文本为**成品字符串**。编译期内置插件可用 `t()`（主程序 i18n 占位层，key 在 `src/locales/zh-CN.json`）——`plugins/ai` 先例；未来运行时第三方插件应自备文案。
- 插件 UI 组件渲染错误由 `PluginErrorBoundary` 隔离（面板/浮动层/模态/设置栏目四个宿主自动包裹，插件无感）。

### 5.1 registerPanel —— 侧边栏面板

```ts
{ id: string; title: string; icon: Component; component: Component
  defaultPlacement?: 'left' | 'right' }   // 缺省 'right'
```

- `component` 为**纯内容组件**（无自带 header/标题/关闭按钮），外壳（DockPanel）统一提供标题栏、图标、关闭、拖拽。
- 自动获得：活动栏图标、左右互通拖拽、delta 排布持久化、默认侧出现。

### 5.2 registerTopBarButton —— 顶部图标条按钮

```ts
{ id: string; title: string; icon: Component
  onClick: () => void                      // 宿主统一 try/catch（抛错仅记日志）
  zone?: 'left' | 'right'                  // 缺省 'left'
  variant?: 'default' | 'primary'
  disabled?: () => boolean                 // 惰性取值，渲染期实时求值
  menu?: PluginTopBarMenuOption[]          // 可选 split-button 下拉（支持递归 group/divider/render） }
```

### 5.3 registerSettingsCategory —— 设置弹窗栏目

```ts
{ id: string; title: string; component: Component }
```

- 组件形态与内置 Settings Section 一致（纯内容；可 `import '@/components/settings/settings-shared.css'` 复用通用行样式）。
- **唯一约束：一个插件至多一个设置栏目**——同一插件二次注册（含换短 id）被拒
  （registry 返回 `{ ok:false, conflict:'id' }` + console.warn，本方法返回 void）；多组配置
  在同一栏目组件内分区分组呈现（分区标题行 + `.setting-row` 序列，参照 `plugins/ai` 的
  `AISettingsPanel`：AI 连接 / 快捷键 / 发散方向三分区）。
- 改键行复用 SDK 导出的 `ShortcutActionRow`（`{ actionKey, label }`，actionKey 用 `api.shortcuts` 查得的完整 key）。

### 5.4 registerContextMenuItem —— 画布右键菜单项

```ts
{ id: string
  scope: 'canvas' | 'selection'   // canvas=无选中（粘贴分支后追加）；selection=有选中节点（内置项之后追加）
  label: string; icon?: Component; danger?: boolean
  when?: (ctx: { selectedNodeIds: string[] }) => boolean      // false 则不出现
  run: (ctx: { selectedNodeIds: string[] }) => void           // 收选中节点 id 的展开拷贝，可安全改写
  children?: (sel: { selectedNodeIds: string[] }) => PluginContextMenuChildItem[] }
// 子项：{ key: string; label: string; icon?: Component; danger?: boolean; action: () => void }
```

- `children` 与 `run` **互斥**：children 存在时父项仅作子菜单分组入口（类型上 `run` 仍必填，给 `() => {}` 空实现——`plugins/ai` 先例）。
- 子项 `key` 的菜单内唯一性由插件自己保证（主程序不加分隔前缀）。
- 插件项追加在内置项之后（登记序），不加分隔线。

### 5.5 registerShortcutAction —— 快捷键动作

```ts
{ id: string
  label: string              // 成品文案（设置面板/冲突提示直接展示）
  scope: 'always' | 'canvas' // always=输入守卫之前；canvas=守卫之后（画布操作用这个）
  defaultChord?: string      // 规范化 chord（如 'mod+shift+g'、'i'）；不给则不设默认键
  run: () => void }          // 无事件参数
// 返回 { ok: boolean; conflict?: 'id' | 'chord' | 'reserved' | 'binding' }
```

四级校验：① 短 id 非法 → `'id'`；② key 冲突 → `'id'`；③ defaultChord 非法/保留键/与全部动作（内置+插件）当前生效绑定冲突 → `'chord'`；④ 通过登记。注册**不改写**用户已有覆盖；用户改键走插件设置栏目（ShortcutActionRow）或「恢复全部默认」。用户键位覆盖持久化在插件配置文件的 `shortcuts` 段。

### 5.6 registerModal —— 模态面板

```ts
{ id: string; title: string; component: Component; width?: number }  // width=内容区宽度 px
// 返回 { ok: boolean; conflict?: 'id' }
```

- `component` 为**纯内容**：外壳 ModalShell 负责标题栏/遮罩/Esc，组件**不要**自己渲染 NModal。
- 打开：`ctx.modal.open('短id') → boolean`（自动拼前缀）。**单实例策略**：已有其他模态打开 → warn + false（不做栈）；未登记的 id → warn + false（fail fast）。
- 关闭：`ctx.modal.close()`（无模态打开时幂等）。

### 5.7 registerFloatingLayer —— 全局浮动层

```ts
{ id: string; title?: string; component: Component }   // 返回 void
```

- 浮动层宿主 `PluginFloatingHost` 常驻应用根级（AppShell），逐条目渲染通用窗口壳
  `FloatingWindow`（`src/components/common/`，与 ModalShell 对称的通用件：props `{ show, title? }`，
  不依赖任何 store / 插件代码）并包错误边界；**插件注册只填内容（+ 可选标题）**——定位（默认
  视口中心）/ 拖拽把手条（title 有才渲染文本，**无关闭按钮**）/ 转场 / Teleport 全部
  由窗口壳提供，组件只写内容区。
- **越界钳制（防拖出程序边界关不掉）**：程序边界 = 视口（window.innerWidth/innerHeight）。
  窗口壳保证自身**完整落在视口内**（关闭入口由插件内容自备，必须始终可被用户触及），
  三个触发点：① 拖动中 clamp（pointerdown 缓存窗口尺寸，move 只做钳制算术）；
  ② show 变 true 时 clamp（复用上次位置前越界检测——面板尺寸可能已变化 / 视口可能
  resize 过，nextTick 实测尺寸后钳制，首次打开 offset 为 0 时同样执行、幂等无害）；
  ③ show=true 的窗口在 window resize 后重新 clamp。某轴窗口尺寸 ≥ 视口时该轴退化为
  居中；钳制只改写 CSS 变量偏移，与转场动画并存不冲突。核心算法为纯函数
  `clampFloatingOffset`（`src/utils/floatingWindow.ts`）。位置记忆仍限于应用会话内
  （不做跨会话持久化）。
- **显隐只由插件负责**：经运行时 API `ctx.floating` / `adapter.for(id).floating`
  （`open/close/toggle/isVisible`，收短 id，未登记 warn + false）——适合生成词浮窗这类
  「由事件触发的悬浮 UI」。条目默认隐藏（open 才可见）；关闭入口由插件内容自备
  （如面板底部「关闭」按钮）；关闭重开回视口中心（越界时按 clamp 规则拉回）。
- **演示载体**：hello 插件的「Hello 演示浮窗」（`plugins/hello/`）——快捷键 **H**
  toggle（`ctx.floating.toggle('float')`），面板内「关闭」按钮调
  `adapter.for('hello').floating.close('float')`（演示「关闭由插件负责」约定）；
  可用于人工验证拖动 / 越界钳制 / 转场。

## 六、生命周期与错误处理

**状态机**：`installed`（已装载未启用）→ `active`（运行中）→ `error`（装载或启用失败）。

**装载流程**（应用启动 `pluginStore.init()` → `installAll`）：

1. 读取启用意愿（`localStorage('aidea-plugins')`，结构 `Record<pluginId, true>`）。
2. 逐条目惰性 `import()` 入口 → 读 `default.manifest` → 清单校验（见第三章）。单插件失败仅置 `error`，不传染。
3. 启用的插件 `activate`：sdkVersion 全等校验 → 校验 setup → 组装 `PluginContext` → **同步**调 `setup(ctx)`。
4. setup 成功 → `active`；**抛错回滚链**：依次执行 `onDispose` 清理函数（单条抛错仅 warn 不阻断）→ `rollbackPluginUi`（从 uiRegistry 移除该插件全部 UI 条目，布局自动收缩）→ 置 `error`。

**规则**：

- `setup` 必须是**同步函数**（异步 setup 的异常不会进入回滚链）。
- `onDispose(fn)` 只增不改；当前无动态卸载（启停重启生效），它主要用于 setup 半程抛错回滚与未来卸载钩子。
- 启停 = 改 localStorage 意愿 + 重启生效；**禁用不清数据**（config/additions 保留，重新启用自然恢复）。

## 七、持久化与数据迁移规范

| 数据 | 存储 | 语义 |
| --- | --- | --- |
| 插件自身配置 | localStorage `aidea-plugin-config.<id>`，结构 `{ version: 1; data: Record<string, unknown>; shortcuts: Record<string, string> }` | 即改即写（深度 watch 落盘）；损坏自愈（结构不符 → 删文件回退空）；`data` 段经 `scope.config` 读写，`shortcuts` 段由键位系统托管 |
| 项目级扩展数据 | additions（随项目文件 `additions` 字段保存/打开） | 换项目隔离；写操作入 undo |
| 启停意愿 | localStorage `aidea-plugins` | 重启生效 |
| 用户键位覆盖 | 插件配置文件 `shortcuts` 段 | 禁用保留，重装恢复 |

**不做旧版兼容**：插件不做跨版本数据迁移，迁移前旧版本留存的数据（旧 localStorage 键、旧项目文件遗留字段）一律不读取，相关设置需用户重新配置。持久化结构变更时按 presets 模式做**自愈**：读取时做结构校验，失败 → 删除存储文件并回退默认值（先例：`utils/pluginConfig.ts` 损坏自愈、presets store `validateStorages`）。

## 八、工程约定

- **目录与入口**：`plugins/<dir>/index.ts` 默认导出 `AideaPlugin`；`id` 必须等于 `<dir>`。子文件组织自由（`components/`、`stores/`、`composables/`、`utils/`…，参照 `plugins/ai/`）。
- **导入**：`@/` 别名（→ `src/`）对插件可用（先例：hello/ai 均直接 import 主程序模块与类型）；插件内部互引建议相对路径。
- **pinia store**：插件可自建 pinia store，但 **id 必须加 `${pluginId}:` 前缀**（`defineStore('ai:aiConfig', …)`），防与主程序或其他插件 id 冲突。优先考虑：纯状态用模块级 `reactive`/组合式函数即可，需要跨组件共享与持久化桥接时才上 store。
- **样式**：`<style scoped>`；禁止硬编码十六进制色值，一律 `var(--color-*)`（主题色经 CSS 变量自动适配亮暗）。
- **UI 文本**：经 `t()`（`import { t } from '@/composables/useT'`），key 加在 `src/locales/zh-CN.json`；注册描述符按第五章总则处理。
- **测试**：放 `plugins/<dir>/__tests__/*.test.ts`（vitest 默认收集，已验证）；happy-dom 环境。管理器/登记表侧测试可注入假 entries（`src/__tests__/plugin/` 先例）。
- **tsconfig**：`plugins/**/*.ts` 已在 include；`.vue` 经 import 链由 vue-tsc 处理。
- **HMR**：插件文件无 accept 时为整页 reload；新插件目录需重启 dev server 或整页刷新后生效。

## 九、规范清单（Do / Don't）

**必须**：

1. 数据写一律经 `adapter.api`（自动入历史）；多步写用 `beginBatch/commitBatch` 合并。
2. UI/快捷键注册一律经 `ctx.register`；注册结果为 `{ ok }` 的检查并 warn。
3. setup 只做注册与只读查询，**写操作由用户交互触发**（禁止启动即改项目数据）。
4. `adapter.for(id)` 只传自己的 `manifest.id`；additions key 禁含 `:`（伪造他人命名空间会被抛错拦截）。
5. 自建 pinia store id 加 `${pluginId}:` 前缀。
6. `onDispose` 登记一切需要清理的副作用（window 监听、定时器、全局单例状态复位）。
7. 需要深拷贝隔离时注意域差异：connection/file/additions 是快照，node 的 `get/children` 是 store 引用——**引用只读，禁止改写**。

**禁止**：

1. 直接 import 主程序 store 写数据（绕过命令层 → 不入历史栈）。
2. 在登记描述符之外自拼 `${pluginId}:` 完整 key（归一是系统职责）。
3. 在 setup 中做异步初始化（异步异常不进回滚链，状态会不可预期）。
4. 依赖 `user?` 尾参的消费行为（当前不消费）。
5. 硬编码色值 / 绕过 `t()` 硬编码中文。
6. 假设存在事件总线、动态卸载、异步 setup——当前 SDK 均未提供（见第十章）。

## 十、已知边界（SDK 未提供的能力）

AI 开发者注意：以下是当前 SDK **不存在**的能力，不要臆造调用：

- **无业务事件总线**（节点增删改/选中/视口变化的订阅）；`manager.onChange` 仅内部用于管理面板渲染，非插件 API。响应数据变化当前用轮询/按需查询实现。
- **无动态卸载/热启停**：启停重启生效；`AideaPlugin.teardown` 契约字段存在但当前不被触发。
- **setup 不支持 async**。
- **shortcuts 域只读**：不能改写用户绑定（改键 UI 由插件设置栏目经 ShortcutActionRow 提供）。
- **file 域无 UI 化打开/保存**：完整导入请 `parse()` 预览后经 `api.node`/`api.project` 组合落地。
- **additions 无加载函数声明机制**：打开项目时数据即已随文件恢复（additions store 统一加载）。
- **模态单实例**：不做栈，打开第二个模态前需先关闭。

若以上边界确需突破（新增注册类型/新 api 域），见第十二章「扩展 SDK」。

## 十一、示例剖析

**`plugins/hello/`**（教学演示）：面板 + 顶栏按钮 + 设置栏目 + 快捷键动作（mod+shift+g）+ 右键菜单项（selection 与 canvas 两个）+ 模态面板；演示 additions 写（`lastRun`）、config 读（`greetingPrefix`）、插件私有组合命令（`summarize`，普通函数无需注册）、批量合并单条历史。

**`plugins/ai/`**（真实功能级）：面板(left) + 设置栏目（发散方向管理）+ 两个快捷键动作（`i` 生成 / `c` 清除）+ 右键「发散」children 子菜单（动态列方向，工厂收 `selectedNodeIds` 经 `api.node.get` 取文本）+ 浮动层（生成词面板，自管显隐）；持久化三件套完整先例——连接配置与方向列表 → config、项目级提示词/模式 → additions（`ai:projectConfig`）、store id 加 `ai:` 前缀。

**建议的 setup 结构**（两个示例一致）：模块顶层 manifest → 模块顶层 `scope = adapter.for(id)` → 默认导出 `{ manifest, setup }`；setup 内按「面板 → 设置栏目 → 快捷键 → 右键菜单 → 模态/浮动层」顺序注册，注册结果不 ok 时 `console.warn`。

## 十二、扩展 SDK（主程序侧）

当现有注册类型/九域 api 不够时，按既有模式扩展（先例：AI 迁移新增的浮动层注册）：

1. **新增 UI 注册类型**：`src/stores/uiRegistry.ts` 加登记表（条目含 `key/pluginId/origin`）+ `registerPluginXxx`（冲突 warn + boolean）+ `removePlugin` 清理覆盖 → `src/plugin/ui.ts` 加 `PluginXxxRegistration` 类型与 `registerXxx`（短 id 校验、warn 模式对齐）→ 新增渲染宿主组件（照 `PluginModalHost.vue`/`PluginFloatingHost.vue`：读表逐条目 `<component :is>` + `PluginErrorBoundary`）→ 宿主挂载点接入布局 → `adapter.ts` re-export 新类型 → 契约测试（`ui-registry.test.ts` 模式）。
2. **扩展既有注册项字段**：`src/plugin/ui.ts` 类型加字段 → 消费点（如 `useCanvasEvents.ts` 的插件菜单映射）透传 → 测试覆盖（先例：右键菜单 `children`）。
3. **新增 api 域**：`src/plugin/api/<domain>.ts` 实现（查询快照化、写经 useCommands）→ `api/index.ts` 装配 → `adapter.ts` re-export 类型 → `api.test.ts` 契约用例。
4. **纪律**：适配层「**只增不改**」——不破坏既有插件调用面；`SDK_VERSION` 仅在破坏性变更时升 major。
