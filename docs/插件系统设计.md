# 插件系统设计（AIDEA）

> 目标：为纯前端 Vue3 + Konva SPA 引入一套**可移植**的插件系统。插件源码放在工程根 `./plugins/`，当前由 Vite `import.meta.glob` 在**编译期自动收集并打包**、运行时按下发开关加载；插件通过**唯一适配层 api 对象**查询项目/视图数据（只读）或执行命令（写，内建可撤销历史）；插件自己需要"多步命令"时写成内部函数，仅供自身使用，**不向主应用注册**。项目级扩展数据经项目文件新增的 `additions` 字段持有（回退项目文件、进撤销栈）。
>
> **边界**：插件**不**新增画布节点类型 / 连线类型，**不**修改节点数据模型；仅通过顶层 `additions` 字段追加插件私有的项目级数据（需注册解析函数）。
>
> **▼ 横切原则 A：可迁移性（最重要约束）**。当前用 Vite 编译期内置加载，仅是「运行环境受限」下的**落地方式**，**不是架构本身**。未来切到 Electron 等桌面端或需要用户现场添加插件时，必然迁为**运行时加载**（用户不应为装一个插件而重新编译整个项目）。因此：
> - **适配层（稳定 SDK）/ api / `additions` / 生命周期状态机一律与「加载方式」解耦**，是稳定不变的"内核契约"。
> - **"加载方式"是唯一可变层**，被抽象成 `PluginSource` 接口；编译期 glob 只是其中一个实现。未来换运行时加载，只替换 `PluginSource` 实现，插件代码与全部能力零改动、零迁移。
> - 插件清单（安装/启停元数据）从第一天就以"运行时可读取"的形态持久化（`localStorage('aidea-plugins')`），不依赖编译期产物。
> - 所有插件能力均通过**插件 id 路由**，不携带任何"编译期模块引用"语义，保证同一份插件在两种加载方式下行为一致。
>
> **▼ 横切原则 B：适配层 = 正式稳定 SDK**。插件只经**适配层（`PluginAdapter`）**与主应用交互，它是**向后兼容、只增不改**的恒定接口契约（见 §5）。适配层内侧的主应用实现可以任意重构（store 改名、useCommands 变化、future 化…），但对外语义承诺不变；需要变化时走 major 升级 + changelog。

本文是 `docs/my-plan.md` 的完善细化，参考但不完全遵循原文。

## 二、核心洞见与派生约束

1. **`./plugins` 自动搜索 = Vite 编译期 glob，而非运行时扫盘。** 浏览器运行时代码无法枚举本地目录。用 `import.meta.glob('../../plugins/**/*.{ts,js,vue}')` 在**编译期**收集所有插件模块并打包。插件代码与主应用一起构建/被 dev HMR 监看，改动自动生效。反过来，插件的运行时形态天然支持完整 TS + SFC——"纯前端无法编译"的约束在本方案下消失。
2. **加载方式是可替换的唯一可变层（可迁移性的落点）。** 插件内核（契约 / api / additions / 状态机）**完全不感知**插件代码怎么来的。加载被抽象为 `PluginSource`：
   - **`StaticPluginSource`（当前，编译期）**：`import.meta.glob` 得到 `{ [key]: () => Module }`。
   - **`RuntimePluginSource`（未来，Electron 等桌面端）**：从本地目录 glob 扫描，动态 `import()` / `loadModule` 加载 `.js`/`.cjs` 插件文件。
   - `PluginManager` 只依赖 `PluginSource` 接口（`list(): {id, loader}[]`）。切 Electron 时写一个新的 `RuntimePluginSource` 并替换注入，**插件本体与全部能力零改动**。
3. **插件 = 源提供的模块实例 + 运行时间表控。** 无论加载方式，启停都不卸载代码文件，而是**不调其 `setup` 并清理其注册项**；启停基于 `manifest.id` 路由。`localStorage('aidea-plugins')` 清单字段不依赖编译期产物。
4. **适配层是插件的唯一稳定接口，api 是其核心。** 插件只写 `PluginAdapter` 语言：经**同一个 api 对象**查询数据（只读）或执行命令（写）。**命令并入 api**——不再有独立的命令类 / 命令表 / 命令注册。写方法内建可撤销历史；复合操作可用 `beginBatch/commitBatch` 合并为单条历史。
5. **数据写唯一入口是 api 内部的 `useCommands`**（主应用唯一写入口）。插件调用 api 写方法即走该入口，一次写 = 单条历史。插件要复合操作就自行组合多个 api 写方法（必要时 `beginBatch/commitBatch`），不提供独立事务 API。
6. **只读一律返回结构化快照**，不跨作用域引用内部 reactive。
7. **`additions` 是项目级扩展数据的唯一落点。** 不进节点字段；由插件在清单里声明加载函数（后续增量），打开项目时恢复、保存时写出；**卸载后该 key 数据仍保留**（重装可恢复），仅无解析器时不可读。
8. **ID 命名空间**：插件 id、面板/按钮/快捷键/设置分类 key、additions key 统一按 `pluginId:...` 归一，冲突拒注册。**插件 id 是跨加载方式共享的唯一路由键**。禁用/启用插件统一通过重启应用生效，不做动态卸载注册。

## 三、整体架构

```
┌──────────────────────────────────────────────────────────────┐
│              ▸ 可变层（唯一允许被替换的部分）◂                │
│   PluginSource（加载方式接口）                                │
│   ├─ StaticPluginSource（当前）：import.meta.glob 编译期收集  │
│   └─ RuntimePluginSource（未来 Electron）：本地目录 glob     │
│       + 动态 import() / loadModule，产出 { id, loader }[]    │
└────────────────────┬─────────────────────────────────────────┘
┌────────────────────▼─────────────────────────────────────────┐
│              ▸ 稳定层（插件内核契约，与加载方式无关）◂         │
│                   插件运行时（PluginsCore）                    │
│  PluginManager: install/启禁用/挂起/错误隔离（按 id 路由）     │
│  PluginAdapter（正式稳定 SDK，向后兼容）:                     │
│      api：只读查询 + 执行命令（写） + stats + 后续 UI 注册     │
└──────┬─────────────────────────────┬─────────────────────────┘
┌──────▼───────────┐        ┌────────▼─────────────────────────┐
│ 插件侧普通函数     │        │ 内核 store / API                 │
│ （插件私有命令）   │◀──────▶│ node/view/project/tags           │
└──────────────────┘        │ useCommands(唯一写入口)+history    │
                            │ projectFile / additionsStore      │
                            └──────────────────────────────────┘
```

- **PluginSource（可变层）**：唯一包装"代码从哪来"的接口。当前实现 `StaticPluginSource`；未来换运行时加载只新增一个 `RuntimePluginSource` 并替换注入，以下所有层不动。
- **PluginAdapter（稳定层核心）**：插件唯一入口，SDK 向后兼容、只增不改。内侧可随主应用重构（store/useCommands 变化对插件不可见）。插件只写适配层语言。
- **内核（稳定层）**：只认 `manifest.id` 路由，不持有任何编译期模块引用。

## 四、插件定义与生命周期

### 4.1 插件模块（插件入口源码，加载方式无关）

```ts
// ./plugins/<name>/index.ts —— 插件入口
export default {
  manifest: {
    id: 'stats',               // 命名空间 id（跨加载方式共享的路由键）
    name: '统计助手',
    version: '0.1.0',
    description: '统计节点/子树数据',
    author: 'aidea',
    sdkVersion: '0',
  },
  setup(ctx: PluginContext): void {
    const { api } = ctx.adapter
    api.node.get('root')                          // 只读查询（分类：node）
    api.node.create('root', 0, 0, '新节点')        // 执行命令（可撤销）
  },
  teardown?(): void,
}
```

编译期它被 `import.meta.glob` 收集为「模块工厂」；未来运行时加载被 `RuntimePluginSource` 读成同一形状的模块对象。**插件的 `manifest` 仅依赖纯 JSON 字段，无任何 Vite/构建 API**——保证同一份插件代码在两套加载下逐字可用。

### 4.2 PluginSource（加载方式接口）

```ts
interface PluginSourceEntry { id: string; loader: () => Promise<{ default?: AideaPlugin; [k:string]: unknown }> }
interface PluginSource {
  /** 扫描"可发现"的插件清单（含未启用的），为 PluginManager 提供候选 */
  list(): PluginSourceEntry[]
}
```

- **`StaticPluginSource`（当前）**：`import.meta.glob('../../plugins/**/index.{ts,js,vue}')`，`list()` → `Object.entries(modules).map(([, loader]) => ({ id: 从路径推断, loader }))`。dev 改代码即 HMR。
- **`RuntimePluginSource`（未来，不实现，仅设计预留）**：`list()` 扫描用户插件目录，逐个 `loader` 动态读入，同样返回 `{ id, loader }`。
- **注入**：`PluginManager(source)` 只依赖 `PluginSource`。切 Electron 时把 `staticPluginSource` 换成 `runtimePluginSource` 注入即可，内核零改动。

### 4.3 启停

- `PluginManager` 以 `manifest.id` 为状态键，`enabled` 存 `localStorage('aidea-plugins')`。启用时 `loader().then(m => m.default)` 取模块并 `setup`；禁用/挂起时清理注册项 + 调 `teardown`。禁用/启用统一通过重启应用生效。

### 4.4 生命周期状态机

```
discovered(PluginSource 扫描到) ─▶ installed(enabled=false)
                          │ 用户启用
                          ▼
                     activating ──(setup 成功)──▶ active
                          │                        │
                          │ setup 抛错/未知 manifest│ 禁用/挂起
                          ▼                        ▼
                     error ◀───────────────── deactivating → installed
```

- `discovered` 状态由 `PluginSource.list()` 触发，进入 `installed`。注册表生命周期完全一致，与加载方式无关。
- 所有插件启停、错误隔离：单插件 `setup` 抛错仅置该插件 `error` 态并在插件管理面板展示，不影响其他插件。

## 五、适配层（PluginAdapter / SDK）

### 5.0 定位：恒稳契约层

适配层是插件与主应用之间的**正式稳定 SDK**，两条铁律：

1. **向后兼容，只增不改**：适配层对外接口一经发布即成为承诺，**只允许新增，不允许修改既有签名/语义**。内部实现怎么变（store 改名、useCommands 参数变化…）都在适配层内部消化，替插件挡住涟漪。
2. **唯一的插件访问入口**：插件 `setup(ctx)` 里的 `ctx.adapter` 是唯一能碰应用能力的地方。插件永远写"适配层语言"，不写"内部实现语言"。

> 与「可迁移性」互为表里：适配层把「内部实现变化」和「加载方式变化」都钉在接口内侧。插件因适配层而稳定。

### 5.1 SDK 版本化

- 适配层公开 `SDK_VERSION = '0'` 常数（major-only）。
- 插件 `manifest.sdkVersion` 声明所需 major；运行时校验与当前 major 匹配，**不匹配 → 该插件禁用**并在插件管理面板提示。

### 5.2 应用 api（分类：查询 + 执行）

**命令并入 api，且按域分包**（node / connection / tag / stylePreset / project / view）。插件经 `ctx.adapter.api.<域>.*` 访问——每个域既是只读查询也是执行命令：

```ts
interface PluginApi {
  // 节点：树查询 + 节点写（增/删/文本/样式/组合/清子级/应用预设）
  node: {
    get(id: string): WhiteboardNode | null
    children(parentId: string): WhiteboardNode[]
    tree(visit: (info: TreeVisitInfo) => void): void
    create(parentId: string, x: number, y: number, text?: string): string
    setText(nodeId: string, text: string): { ok: boolean; conflictRef?: string }
    remove(ids: string[]): void
    group(ids: string[]): string | null
    applyPreset(nodeId: string, preset: { borderColor: string }): void
    // …（完整见 src/types/plugin.ts）
  }
  // 连线
  connection: {
    list(parentId: string): Connection[]
    add(parentId: string, from: string, to: string): string | null
    update(parentId: string, id: string, partial: Partial<Pick<Connection, 'lineStyle'|'strokeWidth'|'strokeColor'|'directed'|'text'>>): void
    applyPreset(parentId: string, id: string, preset: ...): void
  }
  // 标签
  tag: { list(): Tag[]; get(id: string): Tag | undefined }
  // 预设增删改（预留：presets store 接入后填充；应用预设已并入 node/connection）
  stylePreset: {}
  // 项目：历史 + 批量 + 项目统计
  project: {
    undo(): void; redo(): void; clearHistory(): void
    beginBatch(): void; commitBatch(): void; rollbackBatch(): void
    stats(): ProjectStats
  }
  // 视图：活动视图 / 选中 / 切换 / 视图统计
  view: {
    active(): ActiveViewInfo
    selection(): SelectionInfo
    select(nodeId: string, ctrlKey?: boolean): void
    switch(nodeId: string): void
    stats(): ViewStats
  }
}
interface PluginAdapter {
  readonly sdkVersion: string
  api: PluginApi
}
```

写方法一律走主应用 `useCommands`（唯一写入口，自动捕获旧值并入历史栈 → 可撤销）。`project.beginBatch/commitBatch` 可把插件的多步操作合并为单条历史。**插件自己的"多步命令"写成内部普通函数（复用多个 api 写方法），无需注册。**

### 5.3 复合操作（无事务，用内部函数 + api 表达）

插件需要一次性多步操作时，写一个内部函数，在函数体内依次调用多个 api 写方法；如需单条撤销历史，用 `beginBatch/commitBatch` 包裹。**对外不暴露，仅供插件自身使用**：

```ts
// 插件内部私有函数（无需注册）
function summarize(api: PluginApi, focusId: string): string | null {
  const focus = api.node.get(focusId)
  if (!focus) return null
  const text = api.node.children(focusId).map((c) => c.text ?? '').join('、')
  if (!text) return null
  const id = api.node.create(focusId, focus.x + focus.width + 40, focus.y, text)
  api.node.setText(id, `概览：${text}`)   // 两次写各占一条历史
  return id
}
```

## 七、项目文件 `additions`（项目化数据，后续增量）

### 7.1 文件格式（`utils/projectFile.ts` 增字段，版本兼容）

```jsonc
{
  "version": 1,
  "projectName": "...",
  "nodes": [...],
  "tags": [...],
  "additions": {           // 新增：插件项目化数据（键 → 插件原始数据）
    "stats:counter": { "count": 3 }
  }
}
```

- `serializeProject` 增 `additions` 输出；`parseProjectFile` 缺省 `{}` 兜底。
- **卸载后保留策略**：某 key 无对应加载函数时，数据**仍保留**在项目文件与内存中，仅 `api.additions.get` 无加载函数时返回 `undefined`；重装可恢复。

### 7.2 解析与回退

`loadProjectIntoApp(data)` 把 `data.additions` 交给 `additionsStore.load(additions)`；打开时对每个 key 调认证过的加载函数恢复为可用形态，否则保留原始值。保存时全部键值序列化进文件。

### 7.3 写与撤销

插件写 `additions` 经 api（后续开放的 `api.additions.set/remove`）→ `additionsStore` 更新 → history 记录（新增一种 patch 类型）→ **进 undo 且标 dirty**。

## 八、设置栏与插件管理

1. **插件管理栏目**（内置固定分类 `plugins`）：已发现插件列表，每项 name/version/描述、启用开关、错误态展示；不提供"运行时安装新文件"（源码目录由 Vite 编译期管理）。
2. **插件设置栏目**：插件分类排在内置之后、自成一组，组间用**分隔线**隔开。配置写 `localStorage('aidea-plugin-config.<id>')`。

## 九、存储方案

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 插件启停清单 | `localStorage('aidea-plugins')` | id → enabled |

## 十、安全模型

- **同源信任**：不再追求沙箱（编译期内置插件本来就是代码的一部分），专注规范：白名单 api、只读快照、api 写方法唯一写入口、命名空间保留。
- additions 的键须匹配 `pluginId:` 前缀，插件不能读其他插件 key 的解析结果。

```
  constants/plugin.ts            # SDK_VERSION / 命名空间工具
  components/plugin/             # PluginManagerSection.vue
  utils/pluginConfig.ts          # usePluginConfig
  docs/plugin-sdk.md
```

**文件组织原则**：
- `adapter.ts` 是**稳定壳**（对外唯一导出、承诺接口）；内侧实现（store/useCommands）可自由重构，插件不受影响。插件只 import 稳定壳导出或用 `ctx.adapter`，从不 import 内部。
- **api 是全局单一能力入口**：不随插件实例重建，也不创建任何命令表/命令类（已取消）。`createPluginAdapter()` 返回的每个方法在**调用时**惰性取 store/composable。
- 已有 `plugins/hello/` 作为**示例插件**，演示查询 + 执行 + 插件内部私有命令。
