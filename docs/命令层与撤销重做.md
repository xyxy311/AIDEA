# 命令层与撤销重做

## 核心架构

数据写操作统一经命令层 `useCommands`，构成「交互层 → 命令层 → 数据层」三层，撤销/重做由此自然获得。命令层是**唯一数据写入口**：先捕获旧值 → 调 nodeStore action → 构造 `DataPatch` → `history.pushCommand`；历史栈 `history` store 是唯一能直接改 `nodeStore.nodes` 的地方（恢复状态用，不动 store 业务逻辑）。

```
交互层 ──> useCommands ──> nodeStore / project / additions
                  │ DataPatch
                  └─> history.pushCommand（入栈，标 dirty）
```

**例外（不入栈）**：拖拽 mousemove 的 `moveNode`、transform 拖动中的 `resizeNode` 实时渲染不进历史，结束事件才 `commitNodeMove`/`commitNodeResize` 入栈；内联视图矩形缩放是视图状态，一律不入 undo。

## 相关文件

| 文件 | 职责 |
| --- | --- |
| `composables/useCommands.ts` | 命令层：全部数据写动作（建/删/移/字/标签/连线/reparent/batch），无持久化 |
| `utils/command.ts` | 补丁类型与捕获函数：`DataPatch`/`NodeChange`/`ConnectionChange`/`AdditionChange`、`deepClone`/`captureNodeFields`/`captureSubtree`/`captureConnections` |
| `stores/history.ts` | 历史栈：push/undo/redo/coalesce/batch，`runWithViewCoord` 视图协调 |
| `utils/dirtyMarker.ts` | `markDataDirty` 标记未保存 |

## 关键类型与函数

- **`DataPatch`** = `{ nodeChanges, connChanges, additionsChanges? }`。change 均为 `add`/`remove`/`modify`；`modify` 只存变化字段，`add`/`remove` 存完整深拷贝。`ConnectionChange` 额外含 `parentId`/`connectionId`（连线嵌套在父节点 `connections` 数组，恢复需定位父级）。`AdditionChange` 是插件项目级扩展数据变更，`{type:'set'|'remove'}`，undo/redo 按 old/new 直接恢复。
- **`deepClone`**：`JSON.parse(JSON.stringify(toRaw(obj)))`，穿透 Vue reactive 代理；undefined/null 直接返回。
- **`captureSubtree`**：递归收集被删子树所有节点 + 父级中关联这些节点的连线深拷贝（供删除命令的 old/undo 恢复）。
- **history store**：`pushCommand` / `undo` / `redo` / `clear` / `beginBatch` / `commitBatch` / `rollbackBatch` / `runWithViewCoord`。undo 逆序应用、redo 正序应用；`add`⇄`remove` 互换，`modify` 用 `assignFields` 逐一赋值（undefined 会删除字段）。
- **`runWithViewCoord(fn, patch?)`**：包裹一次数据操作，执行后统一做视图协调——清理失效选中、销毁宿主被删/移出层级的无效内联视图、同步内联视图尺寸到被 modify 的宿主节点、当前视图节点无效时沿 `pathToRoot` 回退、清理 `expandedIds`。命令层的 `deleteNodes`/`clearNodeChildren` 和 undo/redo 都经它包裹。

## coalesce 与 batch

- **coalesce（连续编辑合并）**：`pushCommand` 支持 `{ coalesceKey }`。栈顶同 key 且 1s 内（`COALESCE_WINDOW`）时，把新 patch 的 modify new 值并入栈顶（`mergePatch`，保留 old 不变），连续输入合并为单条历史。键按类型取：`text-${sortedKey}`/`style-${sortedKey}`/`tags-${sortedKey}`/`conn-${id}`/`conn-style-${sortedKey}`。
- **batch（复合操作）**：`beginBatch`/`commitBatch`/`rollbackBatch` 包裹，事务内 `pushCommand` 追加到同一个 `batchPatch`，提交时合并为单条历史；`rollback` 丢弃。用于 `groupNodes`（建容器 + reparent）等。**必须配对调用**，否则后续命令被吞进 batch。

## 实现细节与踩坑点

- **历史容量**：`MAX_HISTORY = 50`，超限丢最早。
- **合并即清 redo 栈**：coalesce 后 `future` 清空（产生新历史）。
- **直接改 nodes，不加 store 方法**：history 用局部私有函数直接操作 `nodeStore.nodes`，nodeStore 不新增任何 undo 相关方法。
- **命令层职责**：数据何时写、旧值捕获、视图协调、入栈都在 `useCommands` 收拢；交互层不应绕过它直接改 store（否则不进历史栈）。
