# 插件系统 —— 已实现部分概览

> 简明清单：涉及文件位置 + 一句话职责。详见《插件系统设计.md》的设计细节。

## 结构总览

```
src/plugin/
  adapter.ts      # ★稳定壳：PluginAdapter / PluginContext / AideaPlugin 契约 + createPluginAdapter()（插件唯一入口）
  api/            # 分类应用 api（node / connection / tag / project / view / additions），类型从实现派生
  ui.ts           # UI 注册子系统：pluginId 作用域注册面 + wrapTopBarButton + rollbackPluginUi
  uiMerge.ts      # 合并层：内置目录 ∪ 插件运行时注册表 → 派生元信息（渲染点唯一新依赖）
  manager.ts      # 「加载 + 生命周期」单一模块：collectPluginEntries(编译期 glob 收集) + createPluginContext + PluginManager
src/stores/plugin.ts      # pinia 运行时状态 + UI 注册表（uiPanels/uiTopBarButtons/uiSettingsCategories）+ localStorage('aidea-plugins') 启停持久化
src/stores/additions.ts   # 项目级扩展数据（additions，随项目保存/打开，进 undo，卸载保留）
src/components/settings/PluginsSection.vue    # 设置面板「插件」栏目（插件管理）
src/components/plugin/PluginErrorBoundary.vue # 插件 UI 渲染错误隔离
plugins/hello/index.ts    # 示例插件：演示 api 查询/执行/私有命令 + 三类 UI 注册 + additions
```

## 已实现能力

| 能力 | 说明 |
| --- | --- |
| 分类应用 api | `api.node / connection / tag / project / view / additions`，写方法经 `useCommands` 自动入历史（可撤销） |
| 类型派生 | `XxxApi = ReturnType<typeof createXxxApi>`，签名唯一源头在实现处；快照类型显式标注实现返回类型（`ViewStats`/`ProjectStats`/`ActiveViewInfo` 等），领域契约与派生类型合一。UI 注册项类型亦由实现（`src/plugin/ui.ts`）定义并经 adapter re-export |
| 装载 | 应用启动 `main.ts` 调 `usePluginStore().init()` → `PluginManager.installAll` 扫描装载 |
| 周期 | 识别 manifest / SDK 大版本校验 / `setup` 装载 / `onDispose`（setup 抛错时回滚 + 回滚 UI 注册项）/ 单插件错误隔离 |
| 启停 | 仅持久化 → 重启应用生效；`localStorage('aidea-plugins')` |
| 管理面板 | 设置栏新增「插件」分类（`settings/PluginsSection.vue`），展示清单 + 启停开关 + 状态/错误，重启生效提示 |
| UI 注册 | 插件经 `ctx.adapter.ui.registerPanel / registerTopBarButton / registerSettingsCategory` 注册；合并层渲染（面板/顶栏/设置栏目）；参与布局持久化与拖拽；渲染错误隔离（`PluginErrorBoundary`） |
| additions | 插件项目级扩展数据：`api.additions.set/remove/get/keys`，进 undo/redo，随项目文件 `additions` 字段保存/打开；卸载后键保留 |
| 契约测试 | adapter 契约 + 装载收集 + manager 生命周期 + UI 注册（注册/冲突/落位/回滚）+ additions（store/undo/序列化）+ 组件挂载冒烟 |

## 关键设计点

- **命令不设表**：命令已并入 api，插件私有"多步命令"写成内部函数，无需注册。
- **加载与生命周期同处**：`manager.ts` 是「加载 + 生命周期」单一 cohesive 模块；插件条目由 `collectPluginEntries`（编译期 glob）产出并注入，测试可注入假 entries。未来切运行时加载只替换这个收集点，上层零改动。
- **按插件 id 路由**：插件经 `manifest.id` 路由；UI 注册项与 additions 键统一归一为 `pluginId:key`，不携带任何"编译期模块引用"语义，保证同一份插件在编译期 / 未来运行时加载下行为一致。
- **适配层 = 稳定 SDK**：插件只经 `ctx.adapter`（api + ui）与主应用交互；scope（additions 前缀、UI 归因）由 PluginManager 在构造 PluginContext 时按插件组装，插件侧零感知。
- **UI 渲染走合并层**：ActivityBar / DockPanel / TopBarZone / SettingsModal 不再直连内置目录，统一经 `uiMerge.ts` 派生元信息解析（内置优先、插件兜底）。
- **布局持久化对插件宽容**：归一化合法集 = 内置 ∪「已发现插件」前缀（`isExtraValid`），禁用→启用不丢位置，彻底移除才清除；首次落位经 `layout.ensurePanel/ensureTop`。
- **错误隔离**：单插件 setup 抛错仅置该插件 `error` 态（并回滚其 UI 注册项与 onDispose）；插件 UI 组件渲染错误由 `PluginErrorBoundary` 阻断，不传染主应用。
- **additions 进 undo**：`api.additions.set/remove` 捕获旧值 → `DataPatch.additionsChanges` → history 栈，可撤销/重做，`beginBatch/commitBatch` 合并。
- **测试友好**：`PluginManager` 不感知 pinia / localStorage / Vite glob，启停集合经 `getEnabled` 回调只读注入，可在 vitest 中仅构造源码测试。
