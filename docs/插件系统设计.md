# 插件系统设计（AIDEA）

> 目标：为纯前端 Vue3 + Konva SPA 引入一套**可移植**的插件系统。插件源码放在工程根 `./plugins/`，当前由 Vite `import.meta.glob` 在**编译期自动收集并打包**、运行时按下发开关加载；插件通过**唯一适配层 api 对象**查询项目/视图数据（只读）或执行命令（写，内建可撤销历史）；插件自己需要"多步命令"时写成内部函数，仅供自身使用，**不向主应用注册**。项目级扩展数据经项目文件新增的 `additions` 字段持有（回退项目文件、进撤销栈）。
>
> **边界**：插件**不**新增画布节点类型 / 连线类型，**不**修改节点数据模型；仅通过顶层 `additions` 字段追加插件私有的项目级数据（需注册解析函数）。
>
> **▼ 横切原则 A：可迁移性（最重要约束）**。当前用 Vite 编译期内置加载，仅是「运行环境受限」下的**落地方式**，**不是架构本身**。未来切到 Electron 等桌面端或需要用户现场添加插件时，必然迁为**运行时加载**（用户不应为装一个插件而重新编译整个项目）。因此：
> - **适配层（稳定 SDK）/ api / `additions` / 生命周期状态机一律与「加载方式」解耦**，是稳定不变的"内核契约"。
> - **加载收集是唯一可变点**，收敛在 `manager.ts` 内的 `collectPluginEntries()`（编译期 `import.meta.glob`）。未来换运行时加载，只替换这一个收集点，插件代码与全部能力零改动、零迁移。
> - 插件清单（安装/启停元数据）从第一天就以"运行时可读取"的形态持久化（`localStorage('aidea-plugins')`），不依赖编译期产物。
> - 所有插件能力均通过**插件 id 路由**，不携带任何"编译期模块引用"语义，保证同一份插件在两种加载方式下行为一致。
>
> **▼ 横切原则 B：适配层 = 正式稳定 SDK**。插件只经**适配层（`PluginAdapter`）**与主应用交互，它是**向后兼容、只增不改**的恒定接口契约（见 §5）。适配层内侧的主应用实现可以任意重构（store 改名、useCommands 变化、future 化…），但对外语义承诺不变；需要变化时走 major 升级 + changelog。

本文是 `docs/my-plan.md` 的完善细化，参考但不完全遵循原文。

## 二、核心洞见与派生约束

1. **`./plugins` 自动搜索 = Vite 编译期 glob，而非运行时扫盘。** 浏览器运行时代码无法枚举本地目录。用 `import.meta.glob('../../plugins/**/*.{ts,js,vue}')` 在**编译期**收集所有插件模块并打包。插件代码与主应用一起构建/被 dev HMR 监看，改动自动生效。反过来，插件的运行时形态天然支持完整 TS + SFC——"纯前端无法编译"的约束在本方案下消失。
2. **加载收集是唯一可变点（可迁移性的落点）。** 插件内核（契约 / api / additions / 状态机）**完全不感知**插件代码怎么来的。加载收进 `manager.ts` 的 `collectPluginEntries()`：当前用 `import.meta.glob` 在**编译期**收集并产出 `PluginEntry[]`（`{ id, loader }`）注入 `PluginManager`；未来切 Electron 等桌面端时，只需替换该收集函数、用目录扫描 + 动态 `import()` 产出同一形状，**插件本体与全部能力零改动、零迁移**。
3. **插件 = 源提供的模块实例 + 运行时间表控。** 无论加载方式，启停都不卸载代码文件，而是**不调其 `setup`**、仅持久化启停意愿并重启生效；启停基于 `manifest.id` 路由。`localStorage('aidea-plugins')` 清单字段不依赖编译期产物。
4. **适配层是插件的唯一稳定接口，api 是其核心。** 插件只写 `PluginAdapter` 语言：经**同一个 api 对象**查询数据（只读）或执行命令（写）。**命令并入 api**——不再有独立的命令类 / 命令表 / 命令注册。写方法内建可撤销历史；复合操作可用 `beginBatch/commitBatch` 合并为单条历史。
5. **数据写唯一入口是 api 内部的 `useCommands`**（主应用唯一写入口）。插件调用 api 写方法即走该入口，一次写 = 单条历史。插件要复合操作就自行组合多个 api 写方法（必要时 `beginBatch/commitBatch`），不提供独立事务 API。
6. **只读一律返回结构化快照**，不跨作用域引用内部 reactive。
7. **`additions` 是项目级扩展数据的唯一落点。** 不进节点字段；由插件在清单里声明加载函数（后续增量），打开项目时恢复、保存时写出；**卸载后该 key 数据仍保留**（重装可恢复），仅无解析器时不可读。
8. **ID 命名空间**：插件 id、面板/按钮/快捷键/设置分类 key、additions key 统一按 `pluginId:...` 归一，冲突拒注册。**插件 id 是跨加载方式共享的唯一路由键**。禁用/启用插件统一通过重启应用生效，不做动态卸载注册。

## 三、整体架构

```
┌──────────────────────────────────────────────────────────────┐
│              ▸ 可变层（唯一允许被替换的部分）◂                │
│   manager.ts 内 collectPluginEntries()（加载收集）            │
│   ├─ 当前：import.meta.glob 编译期收集 → PluginEntry[]        │
│   └─ 未来 Electron：目录 glob + 动态 import() → 同一形状      │
└────────────────────┬─────────────────────────────────────────┘
┌────────────────────▼─────────────────────────────────────────┐
│              ▸ 稳定层（插件内核契约，与加载方式无关）◂         │
│            manager.ts（PluginManager：加载 + 生命周期）        │
│  PluginManager: installAll/启禁用/错误隔离（按 id 路由）       │
│  PluginAdapter（正式稳定 SDK，向后兼容）:                     │
│      api：只读查询 + 执行命令（写） + stats + 后续 UI 注册     │
└──────┬─────────────────────────────┬─────────────────────────┘
┌──────▼───────────┐        ┌────────▼─────────────────────────┐
│ 插件侧普通函数     │        │ 内核 store / API                 │
│ （插件私有命令）   │◀──────▶│ node/view/project/tags           │
└──────────────────┘        │ useCommands(唯一写入口)+history    │
                            │ projectFile / additionsStore      │
                            └──────────────────────────────────┘
```

- **collectPluginEntries（可变点）**：包装"插件代码从哪来"，当前为编译期 glob 收集并产出 `PluginEntry[]`；未来换运行时加载只替换此函数。
- **PluginManager（加载 + 生命周期）**：接收注入的 `entries[]` 与 `getEnabled` 回调，完成装载与启停管理，只认 `manifest.id` 路由、不持有编译期模块引用。
- **PluginAdapter（稳定层核心）**：插件唯一入口，SDK 向后兼容、只增不改。内侧可随主应用重构（store/useCommands 变化对插件不可见）。插件只写适配层语言。

## 四、插件定义与生命周期

### 4.1 插件模块（插件入口源码，加载方式无关）

```ts
// ./plugins/<name>/index.ts —— 插件入口
export default {
  manifest: {
    id: 'stats',               // 命名空间 id（跨加载方式共享的路由键）
    name: '统计助手',
    version: '0.1.0',
    description: '统计节点/子树数据',
    author: 'aidea',
    sdkVersion: '0',
  },
  setup(ctx: PluginContext): void {
    const { api } = ctx.adapter
    api.node.get('root')                          // 只读查询（分类：node）
    api.node.create('root', 0, 0, '新节点')        // 执行命令（可撤销）
  },
  teardown?(): void,
}
```

编译期它被 `collectPluginEntries` 的 `import.meta.glob` 收集为「模块工厂」；未来运行时加载读成同一形状的模块对象。**插件的 `manifest` 仅依赖纯 JSON 字段，无任何 Vite/构建 API**——保证同一份插件代码在两套加载下逐字可用。

### 4.2 加载收集（manager.ts 内 collectPluginEntries）

```ts
interface PluginEntry {
  id: string
  loader: () => Promise<{ default?: AideaPlugin; [k:string]: unknown }>
}
```

- **当前（编译期）**：`collectPluginEntries()` 用 `import.meta.glob('../../plugins/**/index.{ts,js}')` 扫描并返回 `PluginEntry[]`；dev 改代码即 HMR。
- **注入**：`PluginManager({ entries: collectPluginEntries(), ... })` 只依赖 `PluginEntry[]`（测试可注入假 entries）。切 Electron 时替换 `collectPluginEntries` 的实现即可，内核零改动、不新增接口壳。

### 4.3 启停

- `PluginManager` 以 `manifest.id` 为状态键，`enabled` 存 `localStorage('aidea-plugins')`。启用时 `loader().then(m => m.default)` 取模块并 `setup`；禁用仅置 `enabled=false` 重启生效（不做运行期卸载，故运行期无 teardown 卸载链；setup 抛错时经 `onDispose` 回滚清理）。禁用/启用统一通过重启应用生效。

### 4.4 生命周期状态机

```
discovered(装载收集扫描到) ─▶ installed(enabled=false)
                          │ 用户启用
                          ▼
                     activating ──(setup 成功)──▶ active
                          │                        │
                          │ setup 抛错/未知 manifest│ 禁用/挂起
                          ▼                        ▼
                     error ◀───────────────── deactivating → installed
```

- `discovered` 状态由装载收集扫描到触发，进入 `installed`。注册表生命周期完全一致，与加载方式无关。
- 所有插件启停、错误隔离：单插件 `setup` 抛错仅置该插件 `error` 态并在插件管理面板展示，不影响其他插件。

## 五、适配层（PluginAdapter / SDK）

### 5.0 定位：恒稳契约层

适配层是插件与主应用之间的**正式稳定 SDK**，两条铁律：

1. **向后兼容，只增不改**：适配层对外接口一经发布即成为承诺，**只允许新增，不允许修改既有签名/语义**。内部实现怎么变（store 改名、useCommands 参数变化…）都在适配层内部消化，替插件挡住涟漪。
2. **唯一的插件访问入口**：插件 `import { adapter } from '@/plugin/adapter'`（全局单例）访问应用能力；注册类操作经 `setup(ctx)` 注入的 `ctx.register`（宿主按 manifest.id 组装，归因不可伪造）。插件永远写"适配层语言"，不写"内部实现语言"。

> 与「可迁移性」互为表里：适配层把「内部实现变化」和「加载方式变化」都钉在接口内侧。插件因适配层而稳定。

### 5.1 SDK 版本化

- 适配层公开 `SDK_VERSION = '0'` 常数（major-only）。
- 插件 `manifest.sdkVersion` 声明所需 major；运行时校验与当前 major 匹配，**不匹配 → 该插件禁用**并在插件管理面板提示。

### 5.2 应用 api（分类：查询 + 执行）

**命令并入 api，且按域分包**（node / connection / tag / project / view，后续增至九域）。插件经 `adapter.api.<域>.*` 访问（adapter 为全局单例，直接 import）——每个域既是只读查询也是执行命令：

```ts
interface PluginApi {
  // 节点：树查询 + 节点写（增/删/文本/样式/组合/清子级/应用预设）
  node: {
    get(id: string): WhiteboardNode | null
    children(parentId: string): WhiteboardNode[]
    tree(visit: (info: TreeVisitInfo) => void): void
    create(parentId: string, x: number, y: number, text?: string): string
    setText(nodeId: string, text: string): { ok: boolean; conflictRef?: string }
    remove(ids: string[]): void
    group(ids: string[]): string | null
    applyPreset(nodeId: string, preset: { borderColor: string }): void
    // … 上述 shape 是概念示意，实际**从实现派生**（ReturnType），不手写接口
  }
  // 连线
  connection: {
    list(parentId: string): Connection[]
    add(parentId: string, from: string, to: string): string | null
    update(parentId: string, id: string, partial: Partial<Pick<Connection, 'lineStyle'|'strokeWidth'|'strokeColor'|'directed'|'text'>>): void
    applyPreset(parentId: string, id: string, preset: ...): void
  }
  // 标签
  tag: { list(): Tag[]; get(id: string): Tag | undefined }
  // 项目：历史 + 批量 + 项目统计
  project: {
    undo(): void; redo(): void; clearHistory(): void
    beginBatch(): void; commitBatch(): void; rollbackBatch(): void
    stats(): ProjectStats
  }
  // 视图：活动视图 / 选中 / 切换 / 视图统计
  view: {
    active(): ActiveViewInfo
    selection(): SelectionInfo
    select(nodeId: string, ctrlKey?: boolean): void
    switch(nodeId: string): void
    stats(): ViewStats
  }
}
interface PluginAdapter {
  readonly sdkVersion: string
  api: PluginApi
  /** 作用域声明：插件命名空间能力（按 id 缓存，重复调用返回同一实例） */
  for(pluginId: string): { additions: AdditionsApi; config: PluginConfigApi }
}
export const adapter: PluginAdapter   // 全局唯一实例，插件直接 import
```

> additions 不在共享 api 中：它是"插件自己的"数据，只经 `for(pluginId)` 作用域实例提供，内部自动拼 `${pluginId}:` 前缀，归属无需插件自报。
>
> `config` 同样仅在作用域实例上（`get/set/remove` 读写 `aidea-plugin-config.<id>` 的 `data` 段），配置文件按插件天然隔离。

写方法一律走主应用 `useCommands`（唯一写入口，自动捕获旧值并入历史栈 → 可撤销）。`project.beginBatch/commitBatch` 可把插件的多步操作合并为单条历史。**插件自己的"多步命令"写成内部普通函数（复用多个 api 写方法），无需注册。**

**接口不手写，从实现派生**：五类 api 与 `PluginApi` 的类型由各域工厂推导（`XxxApi = ReturnType<typeof createXxxApi>`），定义在 `src/plugin/api/`。只读快照（`ViewStats`/`ProjectStats`/`ActiveViewInfo`/`SelectionInfo`/`TreeVisitInfo`）在工厂函数上显式标注返回类型，`ReturnType` 派生后领域契约与实现类型合一，消除"同义不同源"。

**SDK 导出通用 UI 组件**：适配层除 api 外还导出少量通用 UI 组件（首个：`ShortcutActionRow` 动作改键行，`src/components/common/`，props `{ actionKey, label }`，含键帽点击录制、冲突/非法提示、恢复默认）。主应用设置面板与插件设置栏目**共用同一组件实现**；录制/冲突校验逻辑由 shortcuts store 统一承载，插件不直调 store。

### 5.3 复合操作（无事务，用内部函数 + api 表达）

插件需要一次性多步操作时，写一个内部函数，在函数体内依次调用多个 api 写方法；如需单条撤销历史，用 `beginBatch/commitBatch` 包裹。**对外不暴露，仅供插件自身使用**：

```ts
// 插件内部私有函数（无需注册）
function summarizeNode(api: PluginApi, focusId: string): string | null {
  const focus = api.node.get(focusId)
  if (!focus) return null
  const text = api.node.children(focusId).map((c) => c.text ?? '').join('、')
  if (!text) return null
  const id = api.node.create(focusId, focus.x + focus.width + 40, focus.y, text)
  api.node.setText(id, `概览：${text}`)   // 两次写各占一条历史
  return id
}
```

## 六、插件上下文

```ts
interface PluginContext {
  manifest: PluginManifest
  onDispose(fn: () => void): void   // 卸载时自清理副作用
  register: PluginRegisterApi       // UI/快捷键注册面（仅 setup 期间使用）
}
```

**注册与数据操作分离**：adapter 不再经 ctx 提供（插件直接 import 全局单例）；注册是 setup 期间的一次性动作，`register` 由 PluginManager 在 activate 时按 `manifest.id` 组装闭包传入——归因不可伪造，且无需"共享实例假注册面"之类的防御补丁。数据/查询操作随时经 adapter 单例进行。

「只增不改」保证：某插件面向 `sdkVersion=0` 的 api 调用，即使内部换了实现，签名不变，插件无需改动。

## 七、项目文件 `additions`（项目化数据，后续增量）

### 7.1 文件格式（`utils/projectFile.ts` 增字段，版本兼容）

```jsonc
{
  "version": 1,
  "projectName": "...",
  "nodes": [...],
  "tags": [...],
  "additions": {           // 新增：插件项目化数据（键 → 插件原始数据）
    "stats:counter": { "count": 3 }
  }
}
```

- `serializeProject` 增 `additions` 输出；`parseProjectFile` 缺省 `{}` 兜底。
- **卸载后保留策略**：某 key 无对应加载函数时，数据**仍保留**在项目文件与内存中，仅 `scope.additions.get`（`adapter.for(pluginId)` 作用域实例）无加载函数时返回 `undefined`；重装可恢复。

### 7.2 解析与回退

`loadProjectIntoApp(data)` 把 `data.additions` 交给 `additionsStore.load(additions)`；打开时对每个 key 调认证过的加载函数恢复为可用形态，否则保留原始值。保存时全部键值序列化进文件。

### 7.3 写与撤销

插件写 `additions` 经作用域实例 `adapter.for(pluginId).additions`（`set/remove`，内部自动拼 `${pluginId}:` 前缀，key 本身不得含冒号）→ `additionsStore` 更新 → history 记录（新增一种 patch 类型）→ **进 undo 且标 dirty**。

## 八、设置栏与插件管理

1. **插件管理栏目**（内置固定分类 `plugins`）：已发现插件列表，每项 name/version/描述、启用开关、错误态展示；不提供"运行时安装新文件"（源码目录由 Vite 编译期管理）。
2. **插件设置栏目**：插件分类排在内置之后、自成一组，组间用**分隔线**隔开。配置写 `localStorage('aidea-plugin-config.<id>')`（结构 `{ version: 1, data, shortcuts }`：`data` = 插件自由字段，经 `adapter.for(id).config` 读写；`shortcuts` = 该插件动作的键位覆盖；损坏 removeItem 自愈，对齐 presets 模式）。
3. **快捷键改键入口（独占）**：主应用「快捷键」栏目只列内置动作；插件动作的改键 UI 由插件在自己设置栏目经 SDK 导出的 `ShortcutActionRow` 组件 + `api.shortcuts.pluginActions(pluginId)` 只读查询自行承载。数据同源（shortcuts store），两处改键实时一致；「恢复全部默认」仍全量重置含插件动作的覆盖（全局操作语义不变）。**插件键位覆盖独立存储**：主应用 `aidea-shortcuts` 只存内置覆盖，插件覆盖存各插件配置文件的 `shortcuts` 段（启动时一次性迁移旧混存条目，shortcuts store 先迁移后校验）；`assign/reset` 按前缀路由、`bindings` 合并两源；插件禁用配置保留（重装恢复）。

## 九、存储方案

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 插件启停清单 | `localStorage('aidea-plugins')` | id → enabled |
| 插件配置 | `localStorage('aidea-plugin-config.<id>')` | `{ version: 1, data, shortcuts }`；data=插件自由字段（经 `for(id).config`），shortcuts=键位覆盖；损坏自愈 |
| 插件自有统计 | `localStorage('aidea-plugin-data.<id>')` | 非项目化数据 |
| **插件项目化数据** | **项目文件 `additions`** | 随项目保存/打开，进 undo，卸载保留 |
| 节点/连线数据 | 项目文件（不变） | 插件不参与节点字段 |

## 十、安全模型

- **同源信任**：不再追求沙箱（编译期内置插件本来就是代码的一部分），专注规范：白名单 api、只读快照、api 写方法唯一写入口、命名空间保留。
- additions 的键须匹配 `pluginId:` 前缀，插件不能读其他插件 key 的解析结果。归属由 `adapter.for(pluginId)` 作用域工厂保证：additions 仅存在于作用域实例上、内部自动拼前缀，无需插件自报；UI/快捷键注册经宿主组装的 register 闭包，归因同样不可伪造。

## 十一、目录规划（拟）

```
./plugins/<name>/index.ts        # 各插件入口（源码，与加载方式无关）
src/
  types/plugin.ts                # 纯数据契约：PluginManifest / 只读快照类型 + SDK_VERSION
                                  #   （不手写 Api 接口——类型由实现派生）
  plugin/
    manager.ts                   # 「加载 + 生命周期」单一模块：collectPluginEntries()
                                 #   （编译期 glob 收集）+ createPluginContext + PluginManager
                                 #   （合并了原 source.ts / context.ts，收敛为 entries[]+getEnabled）
    adapter.ts                   # ★稳定壳：全局单例 adapter（export const）+ for(pluginId)
                                  #   作用域 + PluginAdapter/PluginContext/AideaPlugin 契约
                                  #   + 重新导出分类 api 与类型（插件统一从这里 import）
    api/                         # 分类应用 api（node/connection/tag/project/view/presets/theme/
                                  #   file/shortcuts；additions/config 不在共享 api，仅经 for(pluginId) 提供）
      index.ts                   #   createPluginApi() 组合 + PluginApi = ReturnType<…>
      node.ts connection.ts tag.ts project.ts view.ts shared.ts additions.ts config.ts
      presets.ts theme.ts file.ts shortcuts.ts
                                  #   每域工厂返回对象 + XxxApi = ReturnType<createXxxApi>
    ui.ts                        # register 注册面组装（PluginRegisterApi）+ wrapTopBarButton + rollbackPluginUi
  stores/uiRegistry.ts           # 登记总表：内置 seed + 插件注册，向 layout/设置面板提供目录
  stores/plugin.ts               # pinia：仅启停 / 生命周期记录（不含 UI 注册表）
  stores/additions.ts            # 项目 additions 数据（load/set/remove/undo，随项目文件序列化）
  components/settings/PluginsSection.vue     # 设置面板「插件」管理栏目（已取代 plugin/PluginManagerSection.vue）
  components/plugin/PluginErrorBoundary.vue  # 插件 UI 渲染错误隔离
  utils/pluginConfig.ts          # usePluginConfig
  docs/plugin-sdk.md
```

**文件组织原则**：
- `adapter.ts` 是**稳定壳**（对外唯一导出、承诺接口，PluginAdapter/PluginContext/AideaPlugin 契约定于此处）；内侧实现（store/useCommands/`api/`）可自由重构，插件不受影响。插件统一从 `@/plugin/adapter` import。
- **api 是全局单一能力入口**：不随插件实例重建，也不创建任何命令表/命令类（已取消）。adapter 单例的每个方法在**调用时**惰性取 store/composable；`for(pluginId)` 组装的作用域实例按 id 缓存复用。
- 已有 `plugins/ai/` 作为**内置插件**（当前唯一内置插件），演示查询 + 执行 + 插件内部私有命令。

## 十三、实施阶段（Roadmap）

### Phase 0 —— 类型与适配层 api（已完成 api 封装 + 示例）
- `types/plugin.ts`：纯数据契约（`PluginManifest` / 只读快照 / `SDK_VERSION`）。**不手写 Api 接口，类型由实现派生**。
- `plugin/api/`：分类应用 api（node/connection/tag/project/view），各域工厂 + `ReturnType` 派生类型，惰性委托 `store / useCommands`。
- `plugin/adapter.ts`：契约定于此（PluginAdapter/PluginContext/AideaPlugin）+ `createPluginAdapter()`，re-export api。
- `plugins/ai/`：内置插件（当前唯一），演示 **查询 + 执行命令 + 插件内部私有命令**（Phase 0 教学示例职责的承载者）。

### Phase 1 —— 接入真实插件装载（已完成）
- `plugin/manager.ts`（合并原 source.ts / context.ts）：`collectPluginEntries()`（`import.meta.glob('../../plugins/**/index.{ts,js}')`）+ `pluginIdFromPath` 路径→id + `createPluginContext` 组装 + `PluginManager`（注入 `{ entries, adapter, getEnabled }`）。识别 manifest / SDK 大版本校验 / `setup` 执行 / `onDispose`（setup 抛错回滚）/ 单插件错误隔离（仅置该插件 `error`）；启停切换**仅持久化**→ 重启应用生效；记录经 `onChange` 订阅暴露。
- `stores/plugin.ts`：pinia 运行时状态（`PluginManager` 实例 + 记录快照），`localStorage('aidea-plugins')` 持久化；`main.ts` 挂载后调用 `init()` 引导装载。
- `components/plugin/PluginManagerSection.vue`：设置面板新增内置「插件」分类（`SettingsModal` 接入），展示已发现插件清单与启停开关，重启生效提示。
- 新增插件默认 `enabled=false`（installed）；经设置面板启用后重启即运行 `setup`（现行规范：setup 只做注册与只读查询，写操作由用户交互触发——先例见 `plugins/ai/` 的 setup）。

### Phase 2 —— additions 与 UI 注册（✓ 已实现）
- `additionsStore` + projectFile 序列化；`registerPanel/topBarButton/settingsCategory`。**每增一类能力遵循同一"只增不改 + 示例 + 契约测试"节奏。**
- 实现落定记录 / 落地与设计的偏差见《插件UI注册与渲染设计.md》§十七。

### Phase 3 —— adapter 全局单例与注册分离（✓ 已实现 2026-09-07）
- 契约调整：`PluginAdapter` 改**全局单例**（`export const adapter`，插件直接 import）+ `for(pluginId)` 作用域承载 additions（共享 api 移除 additions 域、shortcuts 收窄为只读查询）；**注册与数据操作分离**——`PluginContext` 改为 `{ manifest, onDispose, register }`，`ctx.register` 五方法（面板/顶栏/设置栏目/右键菜单/快捷键动作）由 manager 按 `manifest.id` 组装；删除共享实例假注册面（createRejectedUi）。
- 动机：归因不可伪造（宿主组装闭包，插件无法自报家门）；插件 UI 组件可直接 import 单例（撤销"provide scoped adapter"余项）；注册面在 activate 时组装，避开模块加载期 pinia 未激活的时序问题；`for(id)` 按 id 缓存复用，零性能开销。
