# 插件模态面板

## 核心架构

插件模态「登记与运行时分离」：`ctx.register.registerModal` 只把描述符登记进 `uiRegistry.modals` 表（key=`${pluginId}:${id}`，**不进 dock/活动栏派生**），打开/关闭走模态运行时 API，最终都落到全局单实例状态机 `useModalStore`（`activeKey` 单值，无栈）。宿主 `PluginModalHost` 按 activeEntry 单实例渲染；模态是**纯内容组件**（标题栏/遮罩/Esc 由 `ModalShell` 外壳提供）。

## 关键类型和函数

- `ModalRegistration{id,title,component,width?}`（width 缺省 560）；`registerModal` 返回 `{ok:boolean,conflict?:'id'}`。
- `createPluginModalApi(pluginId)`：open 收**短 id**（内部拼 `${pluginId}:` 前缀），方法体内才 useStore（惰性），实例随 for(id) 的 scopeCache 缓存。
- 三条打开入口：`useModalStore().open(完整key)`（应用内，如 SETTINGS_MODAL_KEY）；`ctx.modal.open('短id')`（setup 内）；`adapter.for(id).modal.open('短id')`（插件组件内）。
- `modalStore.open(key)`：同 key 幂等 true；已有其他模态打开 warn+false（后开者让位先开者）；成功路径先 `stopEditing()` 收尾文本编辑。

## 模块内部组织关系和调用链

三入口 → modalStore.open → `activeKey` 单值；宿主渲染 `PluginModalHost → ModalShell → PluginErrorBoundary → <component :is>`。关闭四路径（Esc/遮罩/标题栏关闭钮/程序化 close）都归到 `modalStore.close()`。

## 实现细节和踩坑点

- **键鼠抑制四守卫**：`useKeyboardShortcuts`（抑制全部 scope 含 always）、`useGridMode.canAct`、`useCanvasNavigation`（空格不进入平移）、`useNodeDragging.onWindowMouseMove`（拖拽冻结）都读 `modalStore.hasOpenModal`。刻意不对称：mousemove 兜底做检查，mouseup 兜底**不做**（模态打开前已开始的拖拽松手时仍要 finishDrag/cleanupDragState 自然收尾，否则状态悬挂/监听泄漏）。
- **单实例策略**：同 key 幂等、其它模态打开 warn+false、先 stopEditing。
- **为何无需孤儿兜底**：①运行期注册表不变（启停重启生效，运行期 removePlugin 仅启动期 setup 抛错回滚触发，而 activeKey 是内存态启动期恒 null）；②单实例天然排除；③幽灵 key 入口拦截（createPluginModalApi.open 先查登记表，未登记 warn+false，fail fast）。
- **内置设置面板**：同一状态机的内置模态，key=`SETTINGS_MODAL_KEY`；不在 modals 表中，宿主不渲染、不干预。
