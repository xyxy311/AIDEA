# Adding a UI Language to the App (plug-and-play: no code change, no restart, no rebuild)

The app's UI locales are self-registered: **drop a conforming language pack into a designated directory and it's automatically registered.** Developers (including end users distributing their own packs) don't need to touch any source code or rebuild.

## Where Do Language Packs Go?

| Runtime | Runtime i18n directory |
|---------|------------------------|
| Development (`npm run dev`) | `<repo root>/i18n-runtime/` |
| Production (packaged app) | `userData/i18n/` (on Windows: `%APPDATA%\AIDEA\i18n\`) |

Put a language-pack `.json` file into that directory to register it; delete the file to unregister it.

> **What is `userData`?** It is the Electron "user data directory" (`app.getPath('userData')`) — **not** a `userData` folder inside the project/repo root. On startup the app pins and names it `AIDEA` via `app.setName('AIDEA')`. On **Windows** that resolves to:
>
> ```
> %APPDATA%\AIDEA\        (expands to C:\Users\<username>\AppData\Roaming\AIDEA)
> ```
>
> So in production the runtime i18n directory is actually `%APPDATA%\AIDEA\i18n\`. On first run of the packaged app, the main process (`seedData.ts`) automatically copies `resources/seed/i18n` (which includes `en-US.json`) into it (only filling missing files, never overwriting yours); drop new language files into the same `i18n` directory and they keep getting auto-registered.

## Language Pack Format

Use a full English pack as a template: `i18n-runtime/en-US.json` (bundled by default and also used as the test fixture).

Keep the top-level `@meta` header and change it to the target language:

```jsonc
{
  "@meta": { "id": "es-ES", "label": "Español", "naiveBase": "en-US" },
  "menuBar": { "file": "Archivo", ... }
}
```

| Field | Requirement |
|-------|-------------|
| File name | `<id>.json`, e.g. `es-ES.json` |
| `@meta.id` | **Exactly** equal to the file name (without `.json`); only `letters/digits/_/-` (uppercase allowed, e.g. `zh-CN`, `en-US`) |
| `@meta.label` | The language's own name (write it in that language; not translated, not passed through `t()`), shown in the dropdown |
| `@meta.naiveBase` | naive-ui fallback locale id; defaults to `en-US`. Use naive's own id when it ships that locale (`en-US`→`en-US`), otherwise the closest one |
| Body | Keys **exactly isomorphic** to `zh-CN.json` (protected by `parity.test.ts`); missing keys fall back to Chinese at runtime |

> `naiveBase` values naive-ui already ships (and these are recommended): `zh-CN` / `zh-TW` / `en-US` / `en-GB` / `ja-JP` / `ko-KR` / `de-DE` / `fr-FR` / `es-AR` / `it-IT` / `pt-BR` / `ru-RU`. For other languages without a naive counterpart, use `en-US`. See `src/composables/naiveLocale.ts` for the full list.

## Plug-and-Play Behavior (Three-State Hot Update)

| Action | Behavior |
|--------|----------|
| **Add** a language file | Auto-registered; immediately selectable in the "Settings → Appearance → Language" dropdown; no restart needed |
| **Overwrite** a language file | Re-registered and the strings replaced; if that language is currently active, the UI text refreshes instantly |
| **Delete** a language file | Automatically removed from the dropdown; if that language is currently active, the UI falls back to Chinese (safety net) |

## Validation & Fallback

- **Invalid packs** placed in the directory (no `@meta` / `@meta.id` mismatch with the file name / broken JSON / illegal id in the file name) are **silently skipped** — they don't affect the program or appear in the dropdown.
- `zh-CN` is always built in as the final fallback: even if every runtime locale fails, the UI still falls back to Chinese.
- The app defaults to **English** (`DEFAULT_LOCALE='en-US'`; a fresh install starts in English); the user's choice is stored in `localStorage('aidea-locale')`.

## Notes

- Every locale switch is driven by a single store (`stores/i18n.ts`, available / bundles) plus the reactive chain in `useT`/`App.vue`. Language is a user preference, so only the `id` is persisted (`localStorage['aidea-locale']`).
- Production packaging is wired up: electron-builder copies `i18n-runtime/` (including `en-US.json`) into the installer via `extraResources` as the initial template, and on first run the main process (`seedData.ts`) copies it into `userData/i18n/` (i.e. `%APPDATA%\AIDEA\i18n\` on Windows; only fills missing files, never overwrites) — no manual initialization. New language files added there keep being auto-registered. See also `打包发布.md` (packaging & release).
