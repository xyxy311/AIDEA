# 插件系统架构（AIDEA）

> 供 `插件开发手册.md` / `插件UI注册.md` / `Electron桌面架构.md` / `插件模态面板.md` 交叉引用。本文只描述**当前已落地**的插件系统架构。

---

## 1. 核心架构

插件系统有两条铁律：

1. **可迁移性：加载收集是唯一可变点。** 适配层（SDK）/ api / additions / 生命周期状态机一律与「插件代码怎么来」解耦；只有 `collectPluginEntries()`（加载收集）会变。当前它是纯 Electron 桌面形态：经 Electron 桥扫描插件目录、以运行时协议装载（而非编译期 glob）。换加载方式只替换这一收集点，插件本体与全部能力零改动。
2. **适配层是稳定 SDK：只增不改。** 插件只经 `PluginAdapter` 与主应用交互；对外接口一经发布即成为向后兼容的契约，只允许新增，不允许修改既有签名/语义。适配层内侧的主应用实现（store 改名、useCommands 变化、future 化…）可以任意重构，对外语义承诺不变；需要变化时走 major 升级 + changelog。

分层结构：

```
可变层（唯一可替换）  sources/ 加载收集
   collectPluginEntries() ─ 当前：Electron 桥扫描目录 + 运行时协议装载，产出 PluginEntry[]
        │  （IPC 失败 → 空集兜底）
        ▼
稳定层（插件内核契约）  manager.ts 生命周期
   PluginManager：installAll / 启停 / 错误隔离（全部以 manifest.id 路由）
        │
        ▼
契约  adapter/api.ts  PluginAdapter · PluginApi（十域） · PluginScope(for(id)) · uiRegistry 登记
        │
        ▼
渲染  插件 UI / 派生排布（layout 纯派生）
```

**插件 id 是跨加载方式的唯一路由键。** 无论插件代码由编译期打包还是运行时装载，启停状态、UI 注册归一键（`${pluginId}:${id}`）、additions key 前缀、插件配置文件名都以 `manifest.id` 为归零点；加载方式不携带任何「编译期模块引用」语义，保证同一份插件在两种加载方式下行为一致。

## 2. 相关文件

## 3. 关键类型和函数

### 3.1 契约类型（`src/types/plugin.ts` / `src/plugin/adapter.ts`）

```ts
// types/plugin.ts
export const SDK_VERSION = '0'                          // 适配层 major 版本

export interface PluginManifest {
  id: string            // 命名空间 id（跨加载方式唯一路由键）
  name: string
  version: string
  description?: string
  author?: string
  sdkVersion: string    // 声明的适配层版本，须与 SDK_VERSION 全等，否则禁用
}

// adapter.ts
export interface PluginAdapter {
  readonly sdkVersion: string
  api: PluginApi                                  // 十域：查询 + 执行
  for(pluginId: string): PluginScope              // 命名空间能力（Map 缓存，同 id 同实例）
}

export interface PluginScope {
  additions: AdditionsApi       // 自动拼 `${pluginId}:` 前缀
  config: PluginConfigApi       // 独立配置文件 `aidea-plugin-config.<id>` 的 data 段
  modal: PluginModalApi         // 本插件登记的模态运行时
  floating: PluginFloatingApi   // 本插件登记的浮动层运行时
}

export interface PluginContext {
  manifest: PluginManifest
  onDispose(fn: () => void): void     // 卸载时自清理副作用
  register: PluginRegisterApi         // 注册面（仅 setup 内使用）
  modal: PluginModalApi               // 模态运行时
  floating: PluginFloatingApi         // 浮动层运行时
}

export interface AideaPlugin {
  manifest: PluginManifest
  setup: (ctx: PluginContext) => void // 插件入口的默认导出必须满足它
  teardown?: () => void
}

export const adapter: PluginAdapter = createPluginAdapter()   // 全局单例，插件直接 import
```

### 3.3 生命周期记录

```ts
export type PluginStatus = 'installed' | 'active' | 'error'

export interface PluginRecord {
  id: string; name: string; version: string
  description: string; author: string
  status: PluginStatus
  enabled: boolean          // 持久化"启用意愿"；active 需 enabled=true（启停经"重新加载"生效）
  error?: string            // 单插件错误信息
  entry: PluginEntry
  module?: { default?: AideaPlugin; [k:string]: unknown }
}

export class PluginManager {
  constructor(options: { entries: PluginEntry[]; getEnabled: () => Record<string, boolean> })
  onChange(fn: (records: PluginRecord[]) => void): () => void
  getRecords(): PluginRecord[]
  async installAll(): Promise<void>        // 引导装载：扫描全部 + 逐个 activate
  disposeAll(): void                        // 热清理：逐个 onDispose + 回滚 UI 注册 + 清空记录（"重新加载"用）
  setEnabled(id: string, enabled: boolean) // 仅更新启用意愿 → 重新加载生效
}
```

### 3.4 `adapter.api` 十域总览（`src/plugin/api/index.ts`）

```ts
export function createPluginApi() {
  return {
    node:       createNodeApi(),        // 树查询 + 节点写（增/删/文本/样式/预设/组合/清子级/尺寸/平移/跨父迁移/标签/引用）
    connection: createConnectionApi(),  // 连线查询 + 写
    tag:        createTagApi(),         // 标签查询（list/get）
    project:    createProjectApi(),     // undo/redo/clearHistory + beginBatch/commitBatch/rollbackBatch + stats
    view:       createViewApi(),        // 活动视图/选中/切换 + stats
    presets:    createPresetsApi(),     // 预设样式读取
    theme:      createThemeApi(),       // 主题查询
    file:       createFileApi(),        // 项目文件相关
    shortcuts:  createShortcutsApi(),   // 只读：绑定查询（不承载注册，注册在 ctx.register）
    i18n:       createI18nApi(),        // i18n
  }
}
export type PluginApi = ReturnType<typeof createPluginApi>  // 类型从实现派生，不手写接口
```

要点：
- 每个域既是只读查询也是执行命令；**写一律走主应用 `useCommands`**（唯一写入口，自动捕获旧值、进历史栈 → 可撤销）。复合操作用 `api.project.beginBatch()/commitBatch()` 合并为单条历史。
- 只读一律返回**结构化快照**，不跨作用域引用内部 reactive（`get` 深拷贝）。
- `additions` / `config` **不在共享 api 中**——它们是"插件自己的"，只经 `adapter.for(pluginId)` 作用域实例提供，内部自动拼前缀。
- 接口不手写：各域 `XxxApi = ReturnType<typeof createXxxApi>`，与实现合一。

### 3.5 生命周期状态机

`installAll` 会把 enable 的插件逐个装载并 `activate`；运行期不再有独立的 `discovered` → `activating` → `deactivating` 过渡态（启停只改意愿、重启生效），实际落地状态压缩为三态：

```
installed（已装载候选，未启用）
   │ 用户启用 + 重新加载
   ▼
active   ← activate() 成功，setup 已注册
   │ setup 抛错 / manifest 非法 / SDK 版本不匹配
   ▼
error（单插件错误，不影响其他）
```

- **错误隔离**：装载失败、清单校验失败、SDK 不匹配、`setup` 抛错，仅把该插件置 `error`（`record.error` 展示在管理面板），不中断其它插件。
- **启停与变更生效 = 重新加载**：`setEnabled` 只写 `localStorage('aidea-plugins')` 并改 `record.enabled`，**不卸载代码、不动态调 teardown**。`setup` 的执行与否由 `getEnabled()` 快照决定，因此启停、以及新增/修改/移除插件文件，都在管理面板点击「重新加载」后一步生效（无需退出应用）——store.reload 先 `manager.disposeAll()` 触发各插件 onDispose 清理 + 回滚 UI 注册 + 清浮动层残留，再 `collectPluginEntries()` 重扫目录、重建 manager 并 `installAll()` 重装。

## 4. 模块内部组织关系和调用链

### 4.1 启动装载 → 校验 → setup 注册 → uiRegistry 登记 → 派生渲染

```
main.ts
  └─ pluginStore.init()
       1  subscribePluginChanges(桌面桥推送目录变更 → 仅置 dirDirty，不做热重扫)
       2  await collectPluginEntries()         // sources/desktop：桥扫描目录 → PluginEntry[]
       3  layoutStore.setDiscoveredPluginIds(...)   // 先回填布局发现集（重清洗 delta）
       4  new PluginManager({ entries, getEnabled: readEnabled })
       5  mgr.onChange(records → pluginStore.records)
       6  await mgr.installAll()
             对每个 entry：
               loadRecord(entry, enabled)          // loader() → 读 manifest → 建 PluginRecord
                 校验：manifest 存在、manifest.id 与 entry.id 全等
               if enabled && status !== 'error':
                 activate(id)
                   SDK 版本全等校验
                   取 module.default，校验有 setup
                   context = createPluginContext(manifest)      // 组装 onDispose / register / modal / floating
                   plugin.setup(context)                        // 插件在此调用 ctx.register.* 注册 UI
                     注册转写 → uiRegistry（key = `${pluginId}:${id}`，reactive Map，origin='plugin'）
                   setup 抛错 → context.dispose() + rollbackPluginUi(id) + status=error
               emit() → pluginStore.records 快照
       7  ready = true

渲染：
  layout store 从 uiRegistry 登记表 + delta 纯派生 leftPanels/rightPanels/topLeft/topRight
  DockPanel / TopBarZone / SettingsModal / ContextMenu / ShortcutRow 消费派生目录渲染
```

简图：

```
启动 ─▶ collectPluginEntries()(可变点)
      ─▶ loadRecord()(装载+清单校验) ─▶ activate()(SDK 校验)
      ─▶ setup(ctx){ ctx.register.* } ─▶ uiRegistry 登记总表
      ─▶ layout 纯派生 ─▶ 面板/顶栏/设置/右键菜单/快捷键动作/模态/浮动层渲染
```

## 5. 实现细节和踩坑点

- **`manifest.id === 目录名` 校验**：`loadRecord` 对装载项 `entry.id`（桌面源取自定义插件目录/id）与插件自身 `manifest.id` 做全等校验，不一致即置 `error` 并保留装载源 id 作为路由键。
- **`sdkVersion` 全等校验**：`activate` 校验 `manifest.sdkVersion !== SDK_VERSION` 即置 `error`（不匹配 → 禁用并在管理面板提示）。`SDK_VERSION` 是 major-only，当前 `'0'`。
- **setup 抛错回滚链**：`activate` 捕获 setup 异常后，依次执行 `context.dispose()`（触发全部 `onDispose` 清理，单条抛错不阻断其余）→ `rollbackPluginUi(id)`（`uiRegistry.removePlugin` 清理该插件全部登记，失败仅 warn 不抛出）→ 置 `status='error'` 并写 `error`。防止半激活插件残留面板/按钮/设置栏目。
- **启停与变更 = 只改意愿、重新加载生效**：`setEnabled` 不触发运行期卸载/装载，避免时序与动态注册副作用；运行时间表由装载时的 `getEnabled()` 快照决定。需要立即生效时走「重新加载」：`manager.disposeAll()` 热清理旧插件的 onDispose 副作用并回滚 UI 注册（`uiRegistry.removePlugin`），再重扫目录重建 manager 重装，同一会话内启停、增删改插件都落地。
- **additions 前缀隔离与随项目保存**：所有键统一 `pluginId:` 前缀；`additionsStore.load` 只保留匹配 `<pluginId>:` 的键；写（`set`/`remove`）经 `applyValue` + `history.pushCommand({ additionsChanges })` → **进 undo 且标 dirty**，随项目文件序列化保存。
- **数据写唯一入口 `useCommands`**：node/connection/project 等写方法一律委托 `useCommands`，自动捕获旧值并入历史栈；插件调用 api 写方法即走该入口。复合操作用 `beginBatch/commitBatch`，不提供独立事务 API。个别无对应命令的场景（如 `stripTagFromAllNodes`）直接调 store（不可撤销），是少数例外。
- **站点唯一桥访问点**（`sources/desktop.ts`）：`window.aideaDesktop` 是 renderer 唯一桥访问点；IPC 失败 → console.error + 空集兜底，`info.error` 非空条目被过滤。
- **dev server URL 分支判据**：用 `location.protocol`（http/https → `/plugins/<id>/<entry>` 根相对 URL）而非 `import.meta.env.DEV` 判断是否走 dev server 伺服，避免误判走 `aidea-plugin://` 协议导致双 SDK 实例；动态 `import()` 必带 `@vite-ignore`。
- **布局 delta 重清洗**：装载前先 `setDiscoveredPluginIds` 回填发现集，保证禁用→启用不丢布局位置。
