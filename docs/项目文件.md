# 项目文件

## 核心架构

项目以带版本号的 JSON 文件（`.aidea.json`）存取，序列化/解析是**纯函数** `utils/projectFile.ts`（`serializeProject` / `parseProjectFile`，不依赖 store）。保存位置与磁盘读写全部在 **Electron main 进程**（`dialog` + `fs`）完成，renderer 只经 `window.aideaFile` 窄桥调用、**永不给路径**——文件位置一律由 main 弹原生对话框确定，renderer 仅回传 main 之前产出的记忆路径。编排层 `composables/useProjectFile.ts` 负责 `new/open/save/saveAs`；脏检查用 `utils/dirtyMarker.ts`（模块级回调注册）解耦 history ↔ file store，避免循环依赖。

## 关键类型和函数

- `serializeProject(nodes, projectName, viewState, tags, additions)` → 组装带 `version` 的 JSON 字符串。
- `parseProjectFile(json)` → 校验并返回 `ParsedProject`；版本不匹配抛错；过滤非法节点/连线、根节点兜底、viewState 逐字段补默认。
- `loadProjectIntoApp(data)` 新建/打开共用：`additionsStore.load` → `nodeStore.replaceNodes(整树)` → `tagsStore.replaceTags` → `commands.clearHistory()`（整树替换不可撤销）→ 恢复视图（重置项目/主视图、重建标签页、恢复视口、重建内联视图、选中 prune）。直改数据不走历史栈，故不误置 dirty，载入后由调用方 `markClean()`。
- `fileStore.dirty`（hasUnconfirmed 改写）与 `fileStore.savedPath`（记忆路径决定 Ctrl+S 覆盖或走另存为）。
- IPC 通道：`file:open` / `file:save` / `file:write` / `file:read` + 跨窗口去重 `project:set-path` / `project:claim`（定义于 `bridge.ts` 的 `IPC`）。
- `window.aideaFile` 桥方法：`openProject()` / `saveProject({defaultName, content})` / `writeFile({path, content})` / `readFile({path})` + `setProjectPath(path|null)` / `claimProject(path)`，打开/保存返回可选 `{ canceled: true }`（取消不报错）。

## 模块内部组织关系和调用链

菜单/快捷键 → `useProjectFile` 编排 → 对话框定路径或覆盖 `savedPath`。有记忆路径时 `saveProject` 经桥 `writeFile` 覆盖；无路径走 `saveAsProject`（main `showSaveDialog` + `writeFile` 后记录 path）。`openProject` / `openRecentFile` 载入时一并 `setSavedPath(path)`——打开即记忆磁盘路径，之后 `Ctrl+S` 直接覆盖同一文件。`confirmDiscard()` 在 dirty 时统一弹确认，取消静默返回不报错。

**跨窗口去重**（多窗口场景，见 `Electron桌面架构.md`）：`openProject`（对话框选路径后）与 `openRecentFile`（路径已知、查重前置）载入前先 `claimProject(path)`——若该路径已被**其它**窗口打开，main 已聚焦目标窗口，renderer 拦截本次打开、不替换当前内容并提示 `menuBar.alreadyOpen`；成功打开 / 另存时 `setProjectPath(path)` 登记，新建时 `setProjectPath(null)` 释放，保持去重登记准确（同一窗口重开当前文件不会被误拦截）。

**导出为文本 / 从文本插入**（走通用文件桥 `window.aideaFs`，见 `Electron桌面架构.md`）：
- 导出：保存按钮下拉「导出为文本」→ `buildTextOutline` 把整棵节点树（含根节点）深度优先生成制表符缩进大纲 → `nativeFs.save({mode:'text', defaultName:'<项目名>.txt'})`。
- 插入：打开按钮下拉「从文本插入」→ `TextInsertModal` 模态（直接输入/导入 `txt`，Tab 在光标处插入制表符、横纵双向滚动）→ `insertNodeText(content)` → `parseTextForest` 解析缩进森林 → `layoutTextNodes` 按层排成网格（每层列数 = `floor(√层节点数)`，间距 `TEXT_LEVEL_H_STEP`/`TEXT_LEVEL_V_STEP` 固定）→ 原点放到当前视图已有节点包围盒右侧之外（`TEXT_INSERT_MARGIN`）→ 0 缩进节点作为 `project.currentNodeId` 的直接子节点入树，样式取 `presets.defaultNodePreset?.borderColor`（空回退工厂默认）→ **单条 `history.pushCommand` 历史**（一步撤销/重做）。

## 实现细节和踩坑点

- 格式关键字段：`version` / `nodes` / `tags` / `additions` / `viewState`（含 viewedNodeId、视口、expandedIds、inlineViews、选中、tabs/activeTabId）。
- 前向兼容：可选字段解析补默认——`tags`/节点 `tagIds` 缺省补 `[]`；节点 `tagIds` 裁剪为仅存在于 `tags` 定义内的 id、连线裁剪为两端均在集合内的 id（自愈悬空引用），`viewState.tabs` 缺省回退单视图；版本均保持 1。
- 脏判定来源：命令层数据写入（`history.pushCommand` / undo / redo）→ `dirtyMarker.markDataDirty()` → `fileStore.dirty = true`；`loadProjectIntoApp` 用 `replaceNodes` 直改数据**不误置 dirty**，载入后调用方 `markClean()`。
- 只写可持久化状态：`childrenIndex` / `referenceIndex` / `tagIndex` 是 computed 派生索引不落盘；连线嵌套在父节点 `connections` 随整树序列化；内联视图只存 nodeId+尺寸，viewId 是运行期实例。
- 浏览器 File System Access API / `<input type=file>` / Blob 下载兜底已随纯桌面收敛移除
- i18n：`locales/zh-CN.json` 的 `menuBar`（open/newProjectDone/saved/opened/alreadyOpen/unsavedConfirm/openFailed/saveFailed/unsavedConfirmNeeded/exportToText*/insertText*）与 `common`（confirm/cancel/untitledProject），全部经 `t()`。
- 完成标准：`npm run type-check` 零错误 + `npm run test` 全绿；文件选择/读写为 Electron main 对话框行为，agent 无法在自动化触发，实际保存/打开体验需人工在 Electron 窗口验证。

> 本项目文件桥只服务项目文件。**非项目文件的任意文件读写**（导出为文本、加载模板、读二进制等，含插件端 `api.fs` 域）走通用文件桥 `window.aideaFs` / `useNativeFs`（`fs:*` 通道，见 `Electron桌面架构.md`），不要在 `aideaFile` 上扩展非项目语义。
