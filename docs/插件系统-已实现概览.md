# 插件系统 —— 已实现概览与待办规划

> 简明清单：涉及文件位置 + 一句话职责。详见《插件系统设计.md》的设计细节。
> 本文既描述**当前最终实现形态**，也在末节列出**后续规划（待实现）**，供后续开发对齐。

## 一、结构总览（当前实现形态）

```
src/plugin/
  adapter.ts      # ★稳定壳：PluginAdapter / PluginContext / AideaPlugin 契约 + createPluginAdapter()（插件唯一入口）
  api/            # 分类应用 api（node / connection / tag / project / view / additions），类型从实现派生
  ui.ts           # 插件 UI 注册作用域面：pluginId 作用域三注册 + wrapTopBarButton + rollbackPluginUi
                  #   （注册目标 = uiRegistry 登记总表，插件无感）
  manager.ts      # 「加载 + 生命周期」单一模块：collectPluginEntries(编译期 glob 收集) + createPluginContext + PluginManager
src/stores/uiRegistry.ts     # UI 登记总表：内置目录 seed + 插件注册（origin/pluginId 归因），向 layout/设置面板提供目录
src/stores/layout.ts         # delta 排布：只存用户排布改动，向渲染组件提供实时目录（left/right/top）
src/stores/additions.ts      # 项目级 additions 数据（load/get/未加载保留/随项目文件序列化）
src/stores/plugin.ts         # 仅启停 / 生命周期记录（不管理 UI 注册）
src/components/settings/PluginsSection.vue    # 设置面板「插件」栏目（插件管理）
src/components/plugin/PluginErrorBoundary.vue # 插件 UI 渲染错误隔离
plugins/hello/index.ts    # 示例插件：演示 api 查询/执行/私有命令 + 三类 UI 注册 + additions
```

> **演进说明（6 文件 → 3 文件）**：原过度分层的 `source.ts` / `context.ts` 已并入 `manager.ts`，撤掉 `PluginSource` 接口壳与 `PluginStorage` 注入，收敛为 `entries[]` + `getEnabled` 回调两个最小注入点；`api/stylePreset.ts` 空壳删除（六域→五域，Phase 2 又增 `api/additions.ts` 回六域）；`constants/plugin.ts` 取消（SDK_VERSION 归入 `types/plugin.ts`）。清死代码：`PluginManifest.enabled` 字段、store `enabledIds` 导出、`PluginRecord.plugin` 冗余字段、不可达的 `deactivate`/`teardown` 卸载链。

**api 当前已暴露方法（依实现盘点）** —— 命令层写方法均预留可选尾参 `user?: string`（操作者归因；当前版本不消费，见第四章）
- `node`：查询 `get`/`children`/`hasChildren`/`descendants`/`pathToRoot`/`tree`/`referenceOf`/`getReferenceNodeId`/`referenceableNodes`/`isReferenceNameTaken`/`isChildOf`/`nodesWithTag`；命令写 `create`/`remove`/`setText`/`setTexts`/`setStyle`（`Partial<NodeStyle>`）/`applyPreset`（预设样式对象）/`applyPresetById`（按预设 id，查 presets store）/`group`/`clearChildren`/`resize`/`move`/`reparent`/`alignToGrid`/`setTags`/`resetStyle`；项目级写（不可撤销）`stripTagFromAllNodes`。
- `connection`：查询 `list`/`find`（深拷贝快照）；命令写 `add`/`remove`/`removeByIds`/`delete`/`move`/`update`/`updateStyle`/`updateStyleByIds`/`applyPreset`（预设样式对象，含 name/applyText）/`applyPresetById`（按预设 id，查 presets store）。
- `tag`：`list`（有序副本）/`get`（查）；CRUD `add`/`rename`/`updateColor`/`remove`/`reorder`/`clear`（项目级、不可撤销、不带 user）。
- `project`：`canUndo`/`canRedo`/`undo`/`redo`/`clearHistory`/`beginBatch`/`commitBatch`/`rollbackBatch`/`stats`；项目信息 `projectName`/`setProjectName`；树展开 `expandedIds`/`toggleExpand`/`expand`；标签页 `tabs`/`switchToTab`/`addTab`/`closeTab`；导航/项目级 `enterNodeView`/`resetForNewProject`/`markDirty`（均项目级或视图态，不带 user）。
- `view`：`active`/`selection`/`switch`/`select`/`clearSelection`/`stats`；视口 `stageX`/`stageY`/`stageScale`/`setViewport`；选中 `selectConnection`/`setSelectedNodes`/`pruneSelection`；编辑态 `editingNodeId`/`startEditing`/`stopEditing`；内联视图 `inlineViews`/`addInlineView`/`removeInlineView`/`updateInlineViewSize`；网格 `gridMode`/`setGridMode`/`toggleGridMode`（均视图态，不带 user）。
- `additions`：插件上下文带 `pluginId:` 前缀隔离（key 含冒号抛错，只读 api 的写方法抛错）；`get`/`has`/`keys`/`set`/`remove`（写进 undo，不带 user）。
- 新增域（见第五章）：`presets`（预设 CRUD/分组/筛选只读；**应用预设归 node/connection 域** `applyPresetById`）、`theme`（配色/模式）、`file`（序列化/只读解析/dirty）、`shortcuts`（只读键位查询）。不设 `ai` 域——AI 功能未来迁移为内置插件。

## 四、关键设计点

- **命令不设表**：命令已并入 api，插件私有"多步命令"写成内部函数，无需注册。
- **加载与生命周期同处**（重构收敛）：`manager.ts` 是「加载 + 生命周期」单一 cohesive 模块；插件条目由 `collectPluginEntries`（编译期 glob）产出并注入，测试可注入假 entries。未来切运行时加载只替换这个收集点，上层零改动。
- **按插件 id 路由**：插件经 `manifest.id` 路由；UI 注册项与 additions 键统一归一为 `pluginId:key`，不携带任何"编译期模块引用"语义，保证同一份插件在编译期 / 未来运行时加载下行为一致。
- **适配层 = 稳定 SDK**：插件只经 `ctx.adapter`（api + ui）与主应用交互；scope（additions 前缀、UI 归因）由 PluginManager 在构造 PluginContext 时按插件组装，插件侧零感知。
- **UI 注册走登记总表**：`uiRegistry store` 是唯一登记表（内置目录 seed + 插件注册，条目带 origin/pluginId 归因）；layout 经 delta 排布派生实时目录 `leftPanels`/`rightPanels`/`topLeft`/`topRight`/`unplacedPanels` 供渲染组件读取。
- **delta 排布模型**：localStorage 只存「用户显式改动」（顺序覆盖 / 跨侧移动 / 关闭 = `removed` / 尺寸），渲染目录 = `deriveDockLayout`（`utils/dock.ts`）实时派生——新增内置面板 / 插件注册自动按默认侧出现，无需 ensure* 落位；插件 keys 清洗时「pluginId 前缀 ∈ 已发现插件集合」保留（禁用→启用不丢位置，彻底移除才清除）。
- **错误隔离**：单插件 setup 抛错仅置该插件 `error` 态（并回滚其 UI 注册项与 onDispose）；插件 UI 组件渲染错误由 `PluginErrorBoundary` 阻断，不传染主应用。
- **additions 进 undo**：`api.additions.set/remove` 捕获旧值 → `DataPatch.additionsChanges` → history 栈，可撤销/重做，`beginBatch/commitBatch` 合并。
- **写操作 user 归因（预留参数，暂不消费）**：全部命令层写 api 预留可选尾参 `user?: string`，标记"该操作由谁执行"；当前版本**不在历史层存储/消费**（`HistoryEntry` 无 user 字段，`pushCommand` 不接收，useCommands 无尾参），消费方式（写入历史记录 / 未来协作通道）待定。预留可选参数符合适配层「只增不改」承诺，不破坏既有插件调用。
- **测试友好**：`PluginManager` 不感知 pinia / localStorage / Vite glob，启停集合经 `getEnabled` 回调只读注入，可在 vitest 中仅构造源码测试。

> 三点历史演进已并入上文：① 快照类型打通（`view/project` 工厂显式标注返回类型，`ReturnType` 派生与领域契约合一）；② 布局归一化改「登记总表 + delta 派生」（废 `normalizeDockState`/`uiMerge.ts`/`ensure` 落位，layout store 只存 delta）；③ `stores/plugin.ts` 瘦身为仅启停/生命周期。

## 五、后续规划（待实现）

按优先级排序，前缀标 P0（近期重点）/ P1 / P2（可选增强）。

### 5.1 API 完善（✓ 已完成 2026-09-03）

补足各域未暴露能力 + 新增 presets/theme/file/shortcuts/ai 五域 + 写操作 `user` 归因，均已实现并全量验证（type-check 零错误 + 451 用例全绿）。方法清单见「二、已实现能力」的 api 盘点。落地说明：
- **node**：`resize`/`move`/`reparent`/`alignToGrid`/`setTags`/`resetStyle`（命令写，user 透传）；`setStyle` 扩为 `Partial<NodeStyle>`；引用/层级/标签查询全套。注意 `commitNodeResize`/`commitNodeMove` 签名与直觉不同（前者逐节点入栈、后者仅入栈不写数据），已在实现适配并加 `getNode` 旧值先缓存防污染。
- **connection**：补 `delete`（单条）/`move`/`updateStyle`（按父级批量），`applyPreset` 扩展 name/applyText；只读改深拷贝快照。
- **tag**：store 层本就具备完整 CRUD（`src/stores/tags.ts`），直接接入 `add`/`rename`/`updateColor`/`remove`/`reorder`/`clear`（项目级、不可撤销、不带 user）。
- **project**：项目名、树展开、标签页、`enterNodeView`/`resetForNewProject`/`markDirty`（项目级/视图态，不带 user）。
- **view**：视口、连线选中、编辑态、内联视图、网格全套（视图态，不带 user）。
- **新增域**：`presets`/`theme`/`file`/`shortcuts`（**不设 `ai` 域**——AI 功能未来迁移为内置插件，不需要独立 api 面）。`file` 仅序列化+只读解析（完整导入依赖组件上下文未复刻，可用 `api.node`/`api.project` 组合）；`shortcuts` 只读键位查询。
- **预设应用归位（结构调整）**：`applyNodePreset`/`applyConnectionPreset` 从 presets 域迁为 `api.node.applyPresetById`/`api.connection.applyPresetById`（与既有对象式 `applyPreset` 并存，只增不改）；`presets` 域仅保留 CRUD 与分组/筛选查询。
- **user 归因**：仅在 api 层落地——各域命令写方法预留可选尾参 `user?: string`（签名即契约，暂不消费）。曾实现历史层消费（`HistoryEntry.user` + `pushCommand` 归一 `'unknown'` + `useCommands` 20 个写方法透传），后按需求**已还原**；未来消费方式（写历史记录 / 协作通道）待定。

> 测试：新增 `api-node`/`api-connection`/`api-tag`/`api-project`/`api-view` 用例 + `api.test.ts` 扩五域冒烟断言。

### 5.2 UI 注册面扩展（P1）

- `registerShortcut`（**快捷键**，设计 §一 已规划但未实现）：绑定执行函数，进自定义快捷键体系。
- 更多插件入口类型：**右键菜单项**、画布内工具按钮、状态栏/其他 UI 入口。
- **作用域 UI 组件接入适配层**：当前 `provide('aidea-plugin-adapter')` 未实现，插件面板/设置组件拿不到 per-plugin scoped adapter；插件 UI 组件写数据需先统一补 provide → 经 `ctx.adapter` 能力，避免直调内部工厂（现示例插件用 `createAdditionsApi('hello')` 变通）。
- **非法/冲突注册规范化**：当前非法短 id（含冒号/空白）与命名冲突仅 `console.warn` 不抛错，待定义为可被插件探测的失败返回或抛错。
- **动态卸载钩子**：目前除 onDispose 与 setup 失败回滚外，无独立"卸载 UI 注册"钩子。

### 5.3 能力与存储（P1）

- **插件配置存储**：`localStorage('aidea-plugin-config.<id>')` + `utils/pluginConfig.ts`（`usePluginConfig`），设计 §九 已规划未实现。
- **独立插件数据存储 API**：非项目化 key-value（`localStorage('aidea-plugin-data.<id>')`），设计 §九 已规划——区别于随项目走的 additions。
- **业务事件总线**：节点增删改 / 选中 / 视口变化等业务事件订阅，让插件响应应用内部变化（现仅 `manager.onChange` 生命周期快照）。
- **additions 注册加载函数**：清单声明解析/加载函数（设计 §七「后续增量」），打开项目时恢复可用形态（现 `additions.get` 注释提及"无加载函数"边界，但插件侧声明机制待落实）。

### 5.4 架构演进（P1/P2）

- **运行时加载（Electron/桌面端 / 用户现场装插件）**：替换 `collectPluginEntries()` 为目录扫描 + 动态 `import()`，插件本体与能力零改动（唯一可变点的落地）。
- **布局隔离异步化**：`layout.store` 的插件 key 校验依赖编译期 `collectPluginEntries()` 同步读取；迁运行时加载时 `isPluginKeyValid` 需改异步注入来源。
- **运行时热启停/热卸载**：当前启停仅"记录意愿→重启生效"，无动态卸载注册链路。
- **异步 setup 支持**：当前 `installAll` 串行、setup 同步；支持 async/await 生命周期。
- **HMR 细粒度 hot 重注册**（可选）：glob 打包插件无 accept 时是整页 reload，可做细粒度组件级热更新（dev 体验增强）。

### 5.5 安全模型与测试

- **权限/沙箱边界**：当前同源信任、白名单 api，无进程级隔离；若迁运行时加载他人插件需补沙箱 / 权限声明。
- **测试缺口补齐**：各 api 域命令写已补契约用例（见 5.1）。剩余缺口：additions（前缀隔离/只读写抛错/key 冒号/undo 的细分断言）、ui 设置栏目细节与 topbar 的 zone/variant/menu/disabled 惰性取值、插件间 namespace 冲突与错误插件不残留 UI 的端到端。
