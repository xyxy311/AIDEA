| --- | --- |

**adapter 为全局单例**（`import { adapter } from '@/plugin/adapter'`）：`adapter.api` 九域 + `adapter.for(pluginId)` 作用域（additions + config）；UI/快捷键注册经 `setup(ctx)` 注入的 `ctx.register`（注册与数据操作分离，见第四章）；SDK 另导出通用 UI 组件 `ShortcutActionRow`（动作改键行，`src/components/common/`，插件设置面板复用）。

**api 当前已暴露方法（依实现盘点）** —— 命令层写方法均预留可选尾参 `user?: string`（操作者归因；当前版本不消费，见第四章）

- `connection`：查询 `list`/`find`（深拷贝快照）；命令写 `add`/`remove`/`removeByIds`/`delete`/`move`/`update`/`updateStyle`/`updateStyleByIds`/`applyPreset`（预设样式对象，含 name/applyText）/`applyPresetById`（按预设 id，查 presets store）。
- `tag`：`list`（有序副本）/`get`（查）；CRUD `add`/`rename`/`updateColor`/`remove`/`reorder`/`clear`（项目级、不可撤销、不带 user）。
- `project`：`canUndo`/`canRedo`/`undo`/`redo`/`clearHistory`/`beginBatch`/`commitBatch`/`rollbackBatch`/`stats`；项目信息 `projectName`/`setProjectName`；树展开 `expandedIds`/`toggleExpand`/`expand`；标签页 `tabs`/`switchToTab`/`addTab`/`closeTab`；导航/项目级 `enterNodeView`/`resetForNewProject`/`markDirty`（均项目级或视图态，不带 user）。
- `view`：`active`/`selection`/`switch`/`select`/`clearSelection`/`stats`；视口 `stageX`/`stageY`/`stageScale`/`setViewport`；选中 `selectConnection`/`setSelectedNodes`/`pruneSelection`；编辑态 `editingNodeId`/`startEditing`/`stopEditing`；内联视图 `inlineViews`/`addInlineView`/`removeInlineView`/`updateInlineViewSize`；网格 `gridMode`/`setGridMode`/`toggleGridMode`（均视图态，不带 user）。
- `additions`（经 `adapter.for(pluginId)` 作用域，不在共享 api）：内部自动拼 `${pluginId}:` 前缀（key 含冒号抛错）；`get`/`has`/`keys`/`set`/`remove`（写进 undo，不带 user）。
- 新增域（见第五章）：`presets`（预设 CRUD/分组/筛选只读；**应用预设归 node/connection 域** `applyPresetById`）、`theme`（配色/模式）、`file`（序列化/只读解析/dirty）、`shortcuts`（只读键位查询 + `pluginActions(pluginId)` 列插件登记动作；插件动作注册经 `ctx.register.registerShortcutAction`，见 5.2）。不设 `ai` 域——AI 功能已迁移为内置插件（✅ 见 5.6）。

## 四、关键设计点

- **命令不设表**：命令已并入 api，插件私有"多步命令"写成内部函数，无需注册。
- **加载与生命周期同处**（重构收敛）：`manager.ts` 是「加载 + 生命周期」单一 cohesive 模块；插件条目由 `collectPluginEntries`（编译期 glob）产出并注入，测试可注入假 entries。未来切运行时加载只替换这个收集点，上层零改动。
- **按插件 id 路由**：插件经 `manifest.id` 路由；UI 注册项与 additions 键统一归一为 `pluginId:key`，不携带任何"编译期模块引用"语义，保证同一份插件在编译期 / 未来运行时加载下行为一致。
- **适配层 = 稳定 SDK（全局单例）**：插件 `import { adapter }` 访问 `adapter.api` 九域与 `adapter.for(pluginId)` 作用域（additions 前缀隔离、config 命名空间配置，归属无需插件自报）；UI/快捷键注册经 `setup(ctx)` 注入的 `ctx.register`（PluginManager 按 manifest.id 组装闭包，归因不可伪造）——**注册与数据操作分离**，无"共享实例假注册面"防御补丁。
- **UI 注册走登记总表**：`uiRegistry store` 是唯一登记表（内置目录 seed + 插件注册，条目带 origin/pluginId 归因）；layout 经 delta 排布派生实时目录 `leftPanels`/`rightPanels`/`topLeft`/`topRight`/`unplacedPanels` 供渲染组件读取。
- **delta 排布模型**：localStorage 只存「用户显式改动」（顺序覆盖 / 跨侧移动 / 关闭 = `removed` / 尺寸），渲染目录 = `deriveDockLayout`（`utils/dock.ts`）实时派生——新增内置面板 / 插件注册自动按默认侧出现，无需 ensure* 落位；插件 keys 清洗时「pluginId 前缀 ∈ 已发现插件集合」保留（禁用→启用不丢位置，彻底移除才清除）。
- **错误隔离**：单插件 setup 抛错仅置该插件 `error` 态（并回滚其 UI 注册项与 onDispose）；插件 UI 组件渲染错误由 `PluginErrorBoundary` 阻断，不传染主应用。
- **additions 进 undo**：`api.additions.set/remove` 捕获旧值 → `DataPatch.additionsChanges` → history 栈，可撤销/重做，`beginBatch/commitBatch` 合并。
- **写操作 user 归因（预留参数，暂不消费）**：全部命令层写 api 预留可选尾参 `user?: string`，标记"该操作由谁执行"；当前版本**不在历史层存储/消费**（`HistoryEntry` 无 user 字段，`pushCommand` 不接收，useCommands 无尾参），消费方式（写入历史记录 / 未来协作通道）待定。预留可选参数符合适配层「只增不改」承诺，不破坏既有插件调用。
- **测试友好**：`PluginManager` 不感知 pinia / localStorage / Vite glob，启停集合经 `getEnabled` 回调只读注入，可在 vitest 中仅构造源码测试。

> 三点历史演进已并入上文：① 快照类型打通（`view/project` 工厂显式标注返回类型，`ReturnType` 派生与领域契约合一）；② 布局归一化改「登记总表 + delta 派生」（废 `normalizeDockState`/`uiMerge.ts`/`ensure` 落位，layout store 只存 delta）；③ `stores/plugin.ts` 瘦身为仅启停/生命周期。

### 5.2 UI 注册面扩展（P1）

**✓ 已实现（2026-09-07）：快捷键注册 + 右键菜单注册**

- **快捷键动作注册** `api.shortcuts.registerAction({ id, label, scope, defaultChord?, run })` → `{ ok, conflict? }`：登记进 uiRegistry 新表 `shortcutActions`（key=`${pluginId}:${id}`；shortcuts 域 per-plugin 化 `createShortcutsApi(pluginId | null)`，共享实例传 `null` 拒绝注册——与 additions 同模式，scoped 实例由 manager `createPluginContext` 注入 `manifest.id`）。四级校验：短 id 非法 / key 冲突 / defaultChord 非法 / 保留键或与全部动作当前生效绑定冲突。
- **进自定义快捷键体系**：shortcuts store 的 `bindings`（默认表并入插件动作 defaultChord，overrides 覆盖优先）、`assign`（冲突校验遍历含插件动作，冲突提示对插件填成品 label）、`validate`（含 `:` 的插件命名空间覆盖跳过清理——禁用重启保留，重装恢复）；`useKeyboardShortcuts.runtimeMap` 遍历登记表合并插件动作（无绑定跳过），分发与 scope 守卫零改动。
- **设置面板可改键**：`ShortcutsSection` 动作行 = 内置 `CUSTOM_SHORTCUTS` + 插件登记（内置 label 走 `t(labelKey)`、插件用成品字符串；无绑定显示空）。录制 / 单行恢复默认 / 恢复全部默认对完整 key 直接工作。（后经组件化改造，插件动作改键 UI 独占转移至插件设置栏目，见下方注记。）
- **右键菜单项注册** `api.ui.registerContextMenuItem({ id, scope: 'canvas'|'selection', label, icon?, danger?, when?, run })` → `{ ok, conflict? }`：登记进 uiRegistry 新表 `contextMenuItems`。`useCanvasEvents` 构建菜单时按作用域追加：无选中（粘贴分支）追加 canvas 项、有选中（单选/多选）在「发散」后追加 selection 项；`when({ selectedNodeIds })` 过滤；`run` 收到选中 id 的展开拷贝；不加分隔线（`ContextMenu.vue` 渲染组件零改动）。
- **测试**：新增 `api-shortcuts`（15 用例）/ `useCanvasEvents.pluginMenu`（6 用例），ui-registry / shortcuts store / useKeyboardShortcuts 各扩展，共 24 用例；hello 插件演示两组注册（`greet` 快捷键 `mod+shift+g` + `hello-item` 右键项）。

> 注（同日后续改造「adapter 全局单例 + 注册分离」）：注册统一改走 `setup(ctx)` 注入的 `ctx.register.*`（`registerShortcutAction` 从 api.shortcuts 迁入注册面，四级校验逻辑不变）；`api.shortcuts` 收窄为只读查询（per-plugin 化 `createShortcutsApi(pluginId | null)` 取消）；additions 移出共享 api、仅经 `adapter.for(pluginId)` 作用域提供；adapter 改为全局单例（插件 UI 组件可直接 import，"provide scoped adapter"余项就此撤销，见第四章）。

> 注（快捷键改键组件化 + 独占转移）：改键行抽为通用组件 `ShortcutActionRow`（props `{ actionKey, label }`，经 adapter re-export——SDK 首次导出 UI 组件，主应用 `ShortcutsSection` 与插件设置栏目共用同一实现）；`api.shortcuts` 增 `pluginActions(pluginId)` 只读查询；主应用「快捷键」栏目**只显示内置动作**，插件动作改键 UI 独占转移至插件自身设置栏目（hello 面板已接入演示）；数据同源 shortcuts store，「恢复全部默认」仍全量重置含插件动作的覆盖。

> 注（插件配置持久化 + 快捷键独立存储）：新增 `utils/pluginConfig.ts`（读写 `aidea-plugin-config.<id>`，结构 `{ version: 1, data, shortcuts }`，损坏自愈对齐 presets 模式）与 `stores/pluginConfig.ts`（启动全量加载内存态 + 即改即写）；`PluginScope` 扩展为 `{ additions, config }`（`config.get/set/remove` 读写 data 段，经 `adapter.for(pluginId).config`）。**插件键位覆盖不再混存 `aidea-shortcuts`**（瘦身为只存内置覆盖）：启动时一次性迁移含 `:` 条目至各插件配置文件 `shortcuts` 段（shortcuts store 创建时先迁移后校验），此后 `assign/reset` 按 key 前缀路由存储、`bindings` 合并两源；`resetAll` 仍全量重置（含禁用插件）；插件禁用配置保留（重装恢复语义天然成立）。

**余项**：

- 更多插件入口类型：画布内工具按钮、状态栏/其他 UI 入口。
- **非法/冲突注册规范化**：快捷键/右键菜单/模态注册与**设置栏目（含唯一约束）**已定义可探测返回值 `{ ok, conflict }`（registry 层）；面板/顶栏/浮动层注册仍仅 `console.warn` 不抛错，待统一。
- **动态卸载钩子**：目前除 onDispose 与 setup 失败回滚外，无独立"卸载 UI 注册"钩子。

### 5.4 浮动层注册 + 右键菜单 children 子菜单（✓ 已实现 2026-09）

- **右键菜单 children 子菜单**：`registerContextMenuItem` 支持 `children({ selectedNodeIds })` 工厂——
  产出分组父项（父项仅作分组入口，不挂 action、不执行 run），子项经工厂现场求值（收与 run 相同的
  选中上下文，展开拷贝）映射为叶子菜单项（key/label/icon/danger/action 同名透传）；无 children 的
  注册项仍为扁平项，行为不变。
- **浮动层注册 + 运行时**（✓ 窗口 chrome 宿主化重构 2026-09）：
  - **注册** `ctx.register.registerFloatingLayer({ id, title?, component })`（重复注册冲突拒绝）：
    登记进 uiRegistry 表 **`floatingLayers`**（key=`${pluginId}:${id}`，仅收插件条目；只登记不派生
    布局，不进 dock/活动栏体系）。`title` 可选，渲染到宿主窗口的拖拽把手条。
  - **运行时** `ctx.floating` / `adapter.for(id).floating`（`PluginFloatingApi`，同 modal 运行时
    工厂模式）：`open(id) → boolean`（幂等 true；未登记 → warn + false，fail fast 对齐 modal）、
    `close(id) → void`（幂等）、`toggle(id) → boolean`（返回切换后可见性；未登记 warn + false）、
    `isVisible(id) → boolean`（纯查询）。显隐状态存 **pluginFloating store**
    （`states: Map<key, { visible }>`，多实例逐 key 独立；**不存位置**——拖动偏移是窗口组件
    本地状态，关闭重开回视口中心）。
  - **宿主与职责分工**：`PluginFloatingHost`（AppShell 挂载，与 PluginModalHost 同级）逐条目
    渲染通用窗口壳 **`FloatingWindow`**（`src/components/common/`，泛化通用件——props 为
    `{ show, title? }`，不 import 任何 store / 插件代码，宿主把 pluginFloating store 的
    isVisible 映射为 show；fixed 定位默认视口中心 / pointer capture 拖拽把手条
    （title 有才渲染文本、**无关闭按钮**）/ 转场 / z-index 低于模态遮罩 / Teleport to body），
    slot 内 `PluginErrorBoundary` 包插件内容组件（错误边界留宿主）。**插件注册只填内容 +
    可选标题**；**打开/关闭只由对应插件负责**（浮动层无主应用关闭路径）。与模态对称对照：
    模态单实例（modal store 裁决）/ 位置固定 / 主应用关闭（ModalShell × / Esc）。
  - **越界钳制**（✓ 2026-09）：窗口壳保证自身完整落在视口内（防拖出程序边界关不掉）——
    拖动中 clamp / show 变 true 时复用位置前越界检测（nextTick 实测尺寸）/ show=true 的
    窗口随 window resize 重新 clamp；某轴窗口 ≥ 视口退化为居中。核心算法为纯函数
    `clampFloatingOffset`（`src/utils/floatingWindow.ts`）。位置记忆限于应用会话内。
  - 首个消费者：ai 插件生成词浮动面板（`FloatingAIWordPanel` 已瘦身为纯内容组件，显隐经
    `useAIWordPanel` → `scope.floating`）；hello 插件「Hello 演示浮窗」为 FloatingWindow +
    SDK 浮动层 API 的测试载体（快捷键 H toggle，面板内「关闭」按钮演示关闭由插件负责）。
