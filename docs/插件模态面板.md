# 插件模态面板（Plugin Modal）

> 本文讲插件模态面板的**登记、打开/关闭运行时、宿主渲染与键鼠抑制**。
> 是 `docs/插件系统设计.md` / `docs/插件UI注册与渲染设计.md` 的模态分支细化：
> 模态面板与面板 / 顶栏按钮 / 设置栏目一样登记进 `uiRegistry` 登记总表，
> 但**不进 dock / 活动栏布局派生体系**（只登记，无排布语义），由应用级宿主
> `PluginModalHost` 按 `modalStore.activeKey` 单实例渲染。

---

## 一、概述

- **登记与运行时分离**：`ctx.register.registerModal` 只把描述符（id / 标题 / 内容组件 / 宽度）登记进
  `uiRegistry.modals` 表（key = `${pluginId}:${id}`）；打开 / 关闭走模态运行时 API
  （插件侧 `ctx.modal` / `adapter.for(id).modal`，应用内直接 `useModalStore`），
  最终都落到全局模态状态机 `useModalStore`（`activeKey` 单值，无栈）。
- **单实例**：全应用同一时刻至多一个模态（内置设置面板与插件模态共用同一状态机）。
- **插件模态是纯内容组件**：不自带 `NModal` / 标题栏，外壳由宿主统一提供（与面板「纯内容、
  DockPanel 供壳」同构）；渲染错误经 `PluginErrorBoundary` 隔离到占位。
- **数据只存 id，不存组件**：与其它登记条目一致，持久化层（如有）只存 `${pluginId}:${id}`
  字符串；组件对象由插件 `setup` 现场注册，运行时经登记表还原。

## 二、注册 API（registerModal）

```ts
// 插件 setup(ctx) 内
ctx.register.registerModal({
  id: 'about',              // 插件内短 id（不含 ':' 与空白）；完整 key = `my-plugin:about`
  title: '关于本插件',       // 成品字符串（插件不接主 i18n，与面板 / 菜单项 title 惯例一致）
  component: AboutModal,    // 纯内容组件：不渲染 NModal，外壳由 ModalShell 提供
  // width: 480,            // 可选：内容区宽度（px），缺省 560
})
```

返回 `{ ok: boolean; conflict?: 'id' }`：短 id 非法（空 / 含 `:` / 含空白）或同 key 已注册
→ `ok: false`（`console.warn`，不抛错，其余注册项继续生效）。不同插件同短 id 不冲突
（前缀归一隔离）。

`ModalRegistration` 字段表（`src/types/modal.ts`）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | 是 | 插件内短 id；登记表内归一为 `${pluginId}:${id}` |
| `title` | `string` | 是 | 模态标题（成品字符串） |
| `component` | `Component` | 是 | 纯内容组件（外壳负责标题栏 / 遮罩 / Esc） |
| `width` | `number` | 否 | 内容区宽度（px），缺省 560 |

## 三、打开与关闭（三入口）

打开模态共三条入口，最终都走同一个 `modalStore.open`（单实例裁决一致）：

| 入口 | 调用形态 | id 形态 | 适用场景 |
| --- | --- | --- | --- |
| 应用内组件 | `useModalStore().open(key)` | **完整 key**（内置如 `SETTINGS_MODAL_KEY`；插件模态一般不经此入口打开） | 应用自身的组件 / 面板（如设置按钮直接打开设置模态） |
| 插件 setup 内（逻辑） | `ctx.modal.open('about')` | **短 id**（内部自动拼 `${pluginId}:` 前缀） | 插件命令 / 菜单项 / 快捷键动作 / 顶栏按钮等 setup 上下文 |
| 插件 UI 组件内 | `adapter.for(id).modal.open('about')` | **短 id**（同上） | 插件面板 / 设置栏目 / 模态内容等组件内部（组件里拿不到 `ctx`，`for(id)` 与 additions/config 同源同构） |

- `ctx.modal` 由 manager 组装 `PluginContext` 时注入；`adapter.for(id).modal` 由
  `for(id)` 的 `PluginScope` 提供——两者复用**同一工厂** `createPluginModalApi(pluginId)`
  （`src/plugin/ui.ts`），方法体内才 `useStore`（惰性），实例随 `for(id)` 的
  模块级 scopeCache 缓存（同 id 组件与 setup 拿到同一实例）。
- `close()` 关闭当前模态（幂等）：`modalStore.close()` / `ctx.modal.close()` /
  `adapter.for(id).modal.close()` 等价。
- **选用建议**：拿得到 `ctx`（setup 内 / 经 `ctx.onDispose` 闭包捕获）用 `ctx.modal`；
  组件渲染层用 `adapter.for(id).modal`（与组件内取 additions / config 的写法统一，
  先例：ai 插件 store 经 `adapter.for('ai')` 取作用域实例）；应用内非插件场景直接 `useModalStore`。
- `open` 返回 `boolean`（插件入口）：**未登记的短 id → `console.warn` + `false`**
  （`createPluginModalApi.open` 先查登记表，fail fast 杜绝幽灵 key）；已登记 → 同 key
  幂等 `true`；已有其他模态打开 → `false`（store 内 `console.warn`）。应用内入口
  （`SETTINGS_MODAL_KEY`）不经登记表校验。

示例（泛化占位写法；当前内置插件 ai 未注册模态，`my-plugin` 为插件 id 占位）：

```ts
// a) setup 内：右键菜单项 run 中用短 id 打开
run: () => {
  ctx.modal.open('about')   // → modalStore.open('my-plugin:about')
}

// b) 插件组件内：经 for(id) 的 scope 用短 id 打开
const scope = adapter.for('my-plugin')
scope.modal.open('about')   // → modalStore.open('my-plugin:about')
```

## 四、键鼠抑制机制

模态打开 = 独占交互（`modalStore.hasOpenModal === true`）：

- **鼠标**：`NModal` 全屏遮罩天然拦截画布区域的鼠标事件，无需额外守卫。
- **键盘**：画布相关的 window 级监听共 **4 处守卫**，全部读 `modalStore.hasOpenModal`：

| 守卫位置 | 抑制内容 |
| --- | --- |
| `useKeyboardShortcuts`（keydown 入口最前） | 抑制**全部 scope 的画布快捷键，含 `always`**（文件 / 搜索等也停），模态独占键盘 |
| `useGridMode.canAct()` | 网格键盘状态机整体停摆（方向移动 / 打标签 / 级联等） |
| `useCanvasNavigation`（空格 keydown） | 不进入空格平移模式 |
| `useNodeDragging.onWindowMouseMove` | 拖拽冻结：不激活新拖拽，进行中的移动不再跟随 |

  其中 `useNodeDragging` 是一组**刻意的不对称设计**：`mousemove` 兜底做模态检查（冻结移动），
  而 `mouseup` 兜底**不做**检查——模态打开前已开始的拖拽在松手时仍要经 `finishDrag` /
  `cleanupDragState` 自然收尾提交（commit 入历史栈），否则拖拽状态悬挂、window 监听泄漏。

## 五、关闭方式

四种关闭路径最终都归到 `modalStore.close()`（置 `activeKey = null`）：

1. **Esc**：`NModal` 默认行为 → `ModalShell` 收 `update:show(false)` → `emit('close')`；
2. **遮罩点击**：`ModalShell :mask-closable`（默认开）→ 同上；
3. **标题栏关闭钮**：`NCard closable` → `emit('close')`；
4. **程序化**：`modalStore.close()` / `ctx.modal.close()` / `adapter.for(id).modal.close()`（三者等价）。

宿主 `PluginModalHost` 渲染结构：

```
PluginModalHost（v-if=activeEntry）
└─ ModalShell :show="true" :title :width  @close="modalStore.close()"
   └─ PluginErrorBoundary :plugin-id :name
      └─ <component :is="entry.def.component" />
```

## 六、单实例策略

`modalStore.open(key)`（`src/stores/modal.ts`）：

- 同 key 重复 open → 幂等返回 `true`；
- 已有**其他**模态打开 → `console.warn` + 返回 `false`（不做栈，后开者让位先开者）；
- 成功路径自动做主视图编辑态收尾（文本编辑中先 `stopEditing()`，防止模态浮层与
  节点内联编辑器并存）。

`activeKey` 是唯一状态源：`SettingsModal` 绑 `activeKey === SETTINGS_MODAL_KEY`，
`PluginModalHost` 绑 `activeEntry`（key → `uiRegistry.modals` 条目解析）。

## 七、为什么无需孤儿兜底（入口校验 + 运行期注册表不变）

宿主 `PluginModalHost` **无任何清理逻辑**，只做「登记在册 → 渲染」的纯映射（`v-if`）。
曾经的 watch 兜底（条目消失 → 自动 close）已删除，理由有三：

1. **运行期注册表不变**：插件启停只持久化意愿、重启应用生效（`PluginsSection` /
   plugin store / manager 三处一致约定），不做动态卸载注册。运行期 `removePlugin`
   的唯一触发源是启动期 `installAll` 内 setup 抛错的 `rollbackPluginUi`，而 `activeKey`
   是内存态、启动期恒为 null——时序上不可能有模态打开着条目消失。
2. **单实例模型天然排除**：即使未来运行期注册表缩水，「插件模态开着时条目消失」也不会
   发生——启停开关在设置面板内，模态独占：插件模态开着 ⇔ 设置面板打不开 ⇔ 启停无法发生。
3. **幽灵 key 在入口拦截**：兜底唯一真实价值是「open 未登记 key 的幽灵」（modal store
   不校验登记表，幽灵 key 挂上后 `hasOpenModal = true` → 画布快捷键全失效且无任何可见
   模态）。补法放在插件入口：`createPluginModalApi.open` 先查登记表，未登记 →
   `console.warn` + `false`（fail fast）。

因此 `ctx.modal.open('typo')` 拼错短 id 会立即被拒绝（应用路径 `SETTINGS_MODAL_KEY`
有意不经此校验——modal store 本身保持不校验登记表）；`ctx.modal` / `adapter.for(id).modal`
teardown 后误调同理被入口拒绝，无需显式失效。各入口的 `close` 幂等，无副作用。

## 八、设置面板并入

设置面板是同一状态机的**内置模态**：key 固定为 `SETTINGS_MODAL_KEY`（`'settings'`，
`src/stores/modal.ts` 导出；`modalStore` 单实例策略对内置与插件模态一体生效）。顶部设置按钮
直接 `useModalStore().open(SETTINGS_MODAL_KEY)`（modal store 为全局单例，无注入间接层）；
`SettingsModal` 组件保留独立的模态 UI（两栏结构），仅开关状态并入 modal store，
与 `PluginModalHost`（渲染 `uiRegistry.modals` 条目）互不越界——`SETTINGS_MODAL_KEY`
不在 modals 表中，宿主对它不渲染、不干预（内置模态不经宿主管辖）。
